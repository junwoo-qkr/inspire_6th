## Part 1. 컬렉션에 데이터 담기

컬렉션은 여러 객체를 관리하는 자료구조다. 배열과 비교하면서 값에 접근하는 방식, 순서와 중복 처리 기준을 먼저 구분한다.

### 핵심 개념

| 자료구조 | 길이와 순서 | 중복 처리 | 데이터 접근 |
|---|---|---|---|
| 배열 | 길이 고정, 요소 순서 있음 | 허용 | 인덱스 |
| List의 구현체 `ArrayList` | 요소 수 변경 가능, 추가 순서 유지 | 허용 | 인덱스 |
| Set의 구현체 `HashSet` | 요소 수 변경 가능, 반복 순서 보장 안 함 | 허용하지 않음 | 요소를 기준으로 포함 여부 확인·순회 |
| Map의 구현체 `HashMap` | 항목 수 변경 가능, 반복 순서 보장 안 함 | 키 중복 불가, 값 중복 가능 | 키 |

`List`·`Set`은 `Collection`의 하위 인터페이스이고 `Map`은 별도 인터페이스다. Map과 Set의 순서 특성은 구현체에 따라 달라진다. 같은 키로 Map에 다시 저장하면 기존 값이 교체된다.

### Step 1-1. List 크기와 Set 중복 확인하기

`add`는 값을 추가하고 `size`는 현재 저장된 개수를 반환한다. 집합은 중복 추가가 요소 수를 늘리지 않는다는 점을 비교한다.

**목표**: 배열과 List의 길이 확인 방식을 비교하고 Set의 중복 제거를 관찰한다.

**사용 파일**: 다음은 원본 `main`의 두 부분이다.

set.add("John");

## Part 2. 제네릭 응답과 와일드카드

제네릭은 `<>`에 사용할 타입을 지정해 컴파일러가 저장·조회할 타입을 검사하도록 하는 방법이다. 컬렉션에 저장할 타입을 정하는 데서 시작해, 기존 실습의 DTO 한 개와 DTO 목록을 담는 응답 틀로 적용해 본다.

### 핵심 개념

`ResponseTemplate<T>`는 응답 코드·메시지와 `T data`를 가진다. `getData()`의 반환 타입도 T이므로 응답을 꺼낼 때 지정한 타입이 유지된다. `PersonDTO`는 학생·교사·관리자의 공통 부모이고, 각 하위 객체를 `List<PersonDTO>`에 넣을 수 있다.

| 선언 | 안전하게 읽는 타입 | 안전하게 추가할 수 있는 객체 |
|---|---|---|
| `List<T>` | T | T 및 T의 하위 객체 |
| `List<? extends T>` | T | T 및 T의 하위 객체 |
| `List<? super T>` | Object | T 및 T의 상위 객체 |

와일드카드의 `?`는 아직 구체적으로 정하지 않은 타입을 뜻한다. `? extends T`는 T 또는 하위 타입의 목록을 받을 때 사용하고, `? super T`는 T 또는 상위 타입의 목록을 받을 때 사용한다. 여기서 **허용되는 목록 타입**과 **그 목록에 추가할 수 있는 객체 타입**을 구분해야 한다.

### Step 2-1. DTO 한 개와 DTO 목록을 같은 응답 틀로 전달하기

응답의 바깥 구조는 유지하면서 `data`의 타입을 바꿔 본다. 호출자는 별도 다운캐스팅 없이 데이터를 사용할 수 있다.

**목표**: `ResponseTemplate<PersonDTO>`와 `ResponseTemplate<List<PersonDTO>>`를 비교한다.

**사용 파일**: `GenericsApp.java`, `features/generics/ResponseTemplate.java`, `features/oop/sup/PersonDTO.java`, `features/oop/sub`의 세 DTO. 모두 사전 준비에서 확보했다.

## Part 3. 함수형 인터페이스와 람다식

함수형 인터페이스는 추상 메서드 하나를 가진 인터페이스다. 람다를 사용하면 별도의 구현 클래스를 작성하지 않고 그 추상 메서드의 동작을 지정할 수 있다.

### 핵심 개념

| 인터페이스 | 입력 | 결과 | 실행 메서드 |
|---|---|---|---|
| `Supplier<T>` | 없음 | T | `get()` |
| `Consumer<T>` | T | 없음 | `accept()` |
| `Function<T, R>` | T | R | `apply()` |
| `Predicate<T>` | T | boolean | `test()` |

입력과 반환값의 모양을 보고 인터페이스를 선택한다. 값을 공급하면 Supplier, 출력처럼 값을 사용하고 끝내면 Consumer, 다른 값으로 변환하면 Function, 조건을 판단하면 Predicate다. 메서드 참조는 이미 있는 메서드를 람다 대신 전달하는 표현이다.

### Step 3-1. 함수형 인터페이스 호출과 작업 연결

같은 인터페이스라도 람다 구현이 다르면 다른 계산을 수행한다. Consumer의 `andThen`은 첫 작업이 정상적으로 끝난 뒤 같은 입력으로 다음 작업을 실행한다.

**목표**: 람다 선언과 호출을 구분하고 네 가지 인터페이스의 결과를 확인한다.

**사용 파일**: `StreamApp.java`와 추상 메서드 `int max(int x, int y)`를 가진 `features/lambda/InspireFunction.java`.

.study/08-18/be/javaPractice/src/StreamApp.java

```java
InspireFunction func01 = (x, y) -> x > y ? x : y;
System.out.println("func01 = " + func01.max(100, 200));

InspireFunction func02 = (x, y) -> x + y;
System.out.println("func02 = " + func02.max(100, 200));

Supplier<String> supplier = () -> "Hello!";
System.out.println(supplier.get());

Consumer<String> consumer = (str) -> System.out.println(str.split(" ")[0]);
consumer.accept("consumer test");
consumer.andThen(System.out::println).accept("Hi There");

Function<String, Integer> function = (str) -> {
    return str.length();
};
int len = function.apply("Hello World");
System.out.println("len = " + len);

Predicate<String> predicate = (str) -> str.equals("Coca Cola");
Boolean isFlag = predicate.test("Pepsi");
System.out.println("Pepsi == Coca Cola? " + isFlag);
Boolean isFlag2 = predicate.test("Coca Cola");
System.out.println("Coca Cola == Coca Cola? " + isFlag2);
```

3. Predicate의 Pepsi 입력은 false, Coca Cola 입력은 true임을 확인한다.
4. `max`라는 메서드 이름만으로 결과가 결정되지 않는 이유를 설명한다.

## Part 4. 스트림으로 데이터 가공하기

스트림은 원본 요소를 처리하는 흐름이다. 조건 선택과 변환 과정을 연속된 연산으로 표현한다.

### 핵심 개념

| 단계 | 코드 | 역할 |
|---|---|---|
| 생성 | `stream()` | 원본에서 처리 흐름 생성 |
| 중간 연산 | `filter`, `map` | 조건 선택, 값 변환 |
| 최종 연산 | `collect`, `forEach` | 결과 수집, 요소별 작업 실행 |

`filter`는 조건을 통과한 요소만 남기고, `map`은 각 요소를 다른 값으로 변환한다. 중간 연산은 처리 방법을 연결하고 최종 연산이 실행될 때 요소를 처리한다. 최종 연산을 마친 스트림은 소모되므로 같은 컬렉션을 다시 처리할 때는 새 스트림을 만든다.

### Step 4-1. 반복문과 스트림의 결과 비교하기

이름으로 DTO를 선택하고 이름 문자열만 추출하면 화면에 필요한 값의 목록을 만들 수 있다. 같은 처리를 반복문과 스트림으로 비교한다.

**목표**: student·teacher·manager 중 student를 골라 `[STUDENT]`를 만든다.

**사용 파일**: `CollectionApp.main`의 기존 스트림 부분이다.

.study/08-18/be/javaPractice/src/CollectionApp.java

```java
List<String> filterdList2 = personList.stream()
        .filter(s -> s.getName().startsWith("s"))
        .map(s -> s.getName().toUpperCase())
        .collect(Collectors.toList());

System.out.println(filterdList2);
```

**따라 해보기**

1. `& "$jdkBin\java.exe" -Dfile.encoding=UTF-8 -cp study-bin CollectionApp`을 실행한다.
2. `[STUDENT]`가 출력되는지 확인한다.
3. 바로 위 반복문의 조건 검사·대문자 변환·결과 추가를 스트림의 각 연산과 연결한다.

**확인할 것**

- [ ] 출력이 `[STUDENT]`다.
- [ ] `filter`의 결과는 DTO 흐름, `map` 이후는 문자열 흐름이다.
- [ ] 원본 DTO 세 개에서 조건에 맞는 이름을 골라 새 문자열 목록으로 모으는 흐름을 설명한다.

### Step 4-2. 소모된 스트림을 새로 만들기

최종 연산이 끝난 스트림은 재사용할 수 없다. 원본 목록에서 새 스트림을 만들면 같은 데이터를 다시 처리할 수 있다.

**목표**: 새 스트림을 만드는 한 줄의 역할을 오류 재현으로 확인한다.

**사용 파일**: 원본 `StreamApp.main`의 마지막 스트림 부분.

.study/08-18/be/javaPractice/src/StreamApp.java

```java
Stream<String> stream = brands.stream();
stream.forEach((brand) -> {
    System.out.println(brand.toUpperCase());
});

System.out.println("Stream 사용2: 메서드 참조 방식");
stream = brands.stream();
stream.map(String::toUpperCase).forEach(System.out::println);
```

**따라 해보기**

1. 두 번째 `stream = brands.stream();`만 주석 처리한다.
2. 다시 컴파일하고 StreamApp을 실행해 `IllegalStateException`을 확인한다.
3. 해당 줄의 주석을 해제하고 다시 컴파일·실행한다.

**확인할 것**

- [ ] 스트림을 재사용하면 오류가 난다.
- [ ] 새 스트림을 만들면 두 번 모두 대문자 목록이 출력된다.

### 소모된 스트림 재사용

**증상**: 두 번째 처리에서 `IllegalStateException`이 발생한다.

**해결**: 두 번째 처리 전에 `brands.stream()`으로 새 스트림을 만든다.
