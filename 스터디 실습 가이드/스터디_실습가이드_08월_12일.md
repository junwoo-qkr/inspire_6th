## Part 1. 메서드와 DTO의 데이터 흐름

메서드는 입력을 받아 처리 결과를 반환한다. DTO는 관련 값을 묶어 전달하는 객체로, 요청을 읽고 응답을 반환하는 흐름을 만들 수 있다.

### 핵심 개념

| 개념 | 역할 |
| --- | --- |
| 매개변수 / 인자 | 선언부에서 받을 변수 / 호출할 때 전달하는 값 |
| 요청 DTO | 관련 입력값을 하나의 객체로 전달 |
| 응답 DTO | 상태와 메시지 등 여러 결과를 반환 |
| getter | 객체에 저장된 값을 읽음 |
| `equals()` | 문자열의 내용 비교 |

### Step 1-1. 두 입력 방식으로 응답 받기

개별 문자열을 받는 메서드와 DTO를 받는 메서드를 각각 호출한다. 블로그의 두 번째 메서드는 제목이 `title2`와 다를 때 성공하는 조건이므로 이 조건을 그대로 적용한다.

**목표**: 입력 → 메서드 호출 → 조건 비교 → 응답 객체의 흐름을 출력으로 확인한다.

**사용 파일**: 아래 파일은 필요한 DTO 선언까지 포함한다.

스터디 실습 가이드/실습/0812/DtoFlow.java

```java
import lombok.AllArgsConstructor;
import lombok.Getter;

@Getter @AllArgsConstructor
class BlogRequestDTO {
    private Integer id;
    private String title;
    private String content;
    private String email;
}

@Getter @AllArgsConstructor
class BlogResponseDTO {
    private int status;
    private String message;
}

public class DtoFlow {
    // 개별 인자를 받아 제목이 title1이면 성공 응답을 반환한다.
    public BlogResponseDTO register(String title, String content, String email) {
        if ("title1".equals(title)) {
            return new BlogResponseDTO(201, "OK");
        }
        return new BlogResponseDTO(400, "FAIL");
    }

    // DTO의 참조값을 전달받고, 제목이 title2와 다르면 성공한다.
    public BlogResponseDTO register2(BlogRequestDTO request) {
        if (!"title2".equals(request.getTitle())) {
            return new BlogResponseDTO(201, "OK");
        }
        return new BlogResponseDTO(400, "FAIL");
    }

    public static void main(String[] args) {
        DtoFlow app = new DtoFlow(); // 인스턴스 메서드를 호출할 객체
        // new String으로 새 객체를 만들어도 내용으로 비교한다.
        BlogResponseDTO first = app.register(new String("title1"), "Body", "mail");
        BlogRequestDTO request = new BlogRequestDTO(1, new String("title2"), "Body", "mail");
        BlogResponseDTO second = app.register2(request);
        System.out.println(first.getStatus() + ":" + first.getMessage()); // 201:OK
        System.out.println(second.getStatus() + ":" + second.getMessage()); // 400:FAIL
    }
}
```

**따라 해보기**

1. 파일을 UTF-8로 저장하고 현재 실습 폴더에서 컴파일·실행한다.
2. 요청 DTO의 제목을 `other`로 바꿔 두 번째 출력이 `201:OK`로 바뀌는지 확인한다.
3. 첫 메서드의 비교를 `title == "title1"`로 바꿔 결과를 비교하고 `equals()`로 복구한다.


## Part 2. 메모리와 클래스·객체의 상태

객체에 속한 필드와 클래스에 속한 필드를 비교하면 참조와 공유 상태를 구분할 수 있다. 메서드 호출은 스택 프레임의 생성과 종료로 이해한다.

### 핵심 개념

| 구분 | 역할 |
| --- | --- |
| Heap | 인스턴스와 배열을 위한 메모리 |
| JVM Stack | 스레드별 메서드 호출 프레임 관리 |
| Method Area | 클래스별 구조와 메서드 정보 관리 |
| 인스턴스 필드 | 객체별 상태 |
| static 필드 | 클래스에 속한 상태 |
| final 변수 | 초기 대입 후 재대입 제한 |

GC는 도달할 수 없는 객체를 회수 대상으로 삼으며 실제 실행 시점과 정책은 JVM 구현과 설정에 따른다. 아래 출력은 필드의 공유 여부를 관찰하며 물리적 메모리 위치나 GC 실행 시점을 측정하지 않는다.

### Step 2-1. 객체별 값과 공유 값 비교하기

서로 다른 두 객체를 생성하고 한 객체의 필드만 변경한다. 이어 클래스 필드를 변경해 접근 대상과 의미를 비교한다.

**목표**: 인스턴스 멤버와 static 멤버의 접근 방식, final의 재대입 제한을 확인한다.

**사용 파일**: 별도 라이브러리가 필요 없는 실행 클래스이다.

스터디 실습 가이드/실습/0812/MemoryPractice.java

```java
public class MemoryPractice {
    private String message = "original"; // 객체마다 가지는 값
    private static String shared = "shared"; // 클래스에 속한 값
    private static final int MAX_TRIES = 10; // 재대입하지 않는 상수

    private void show() {
        System.out.println(message); // 호출한 객체의 필드 출력
    }

    public static void main(String[] args) {
        MemoryPractice first = new MemoryPractice();
        MemoryPractice second = new MemoryPractice();
        first.message = "changed";
        first.show();  // changed: static main에서도 객체 참조로 접근
        second.show(); // original: 별도 객체의 필드 유지
        MemoryPractice.shared = "updated";
        System.out.println(MemoryPractice.shared); // updated
        System.out.println(MAX_TRIES); // 10
        // MAX_TRIES = 20; // 주석 해제 시 final 재대입 컴파일 오류
    }
}
```

**따라 해보기**

1. 아래 명령으로 실행한다.
2. `first.show()`에 중단점을 설정해 `main → show → main` 호출 흐름을 관찰한다.
3. final 재대입 줄의 주석을 해제하고 컴파일 오류를 확인한 다음 복구한다.

```powershell
# 실행 위치: '스터디 실습 가이드\실습\0812'
& "$jdk\javac.exe" -encoding UTF-8 MemoryPractice.java
& "$jdk\java.exe" -cp . MemoryPractice
```

**확인할 것**

- [ ] 출력이 `changed`, `original`, `updated`, `10` 순서이다.
- [ ] static 메서드에서 객체 참조로 인스턴스 메서드를 호출한다.
- [ ] final 재대입은 컴파일 단계에서 제한된다.

**발표 포인트**: final 참조 변수의 재대입 제한과 참조 대상 객체의 변경 가능성은 별개이다.

## Part 3. 연산자와 실행 흐름 제어

연산자는 값을 계산하고, 조건문은 실행할 경로를 선택한다. 반복문은 같은 처리를 되풀이하며 break와 continue로 진행을 조절한다.

### 핵심 개념

| 문법 | 실행 방식 |
| --- | --- |
| `&&`, `\|\|` | 왼쪽 값으로 결정되면 오른쪽 평가 생략 |
| `&`, `\|` | boolean 피연산자에서는 양쪽 평가 |
| 삼항 연산자 | 조건에 따라 두 값 중 하나 선택 |
| switch 표현식 | case에 대응하는 값을 반환 |
| for / while | 본문 실행 전 조건 검사 |
| do-while | 본문 실행 후 조건 검사 |
| break / continue | 반복 종료 / 현재 회차의 나머지 생략 |
| 레이블 | 지정한 바깥 반복문을 종료할 때 사용 |

### Step 3-1. 출력 순서로 조건과 반복 확인하기

한 실행 파일 안에서 짧은 예제를 순서대로 실행한다. 출력 앞의 이름을 보고 어떤 연산과 반복에서 나온 결과인지 구분한다.

**목표**: 증감 시점, 정수 나눗셈, 조건 선택과 반복 제어를 비교한다.

**사용 파일**: 아래의 짧은 루프들을 하나씩 변경하며 실행한다.

스터디 실습 가이드/실습/0812/FlowPractice.java

```java
public class FlowPractice {
    public static void main(String[] args) {
        int count = 1;
        System.out.println("post=" + count++); // post=1: 사용 후 count = count + 1
        System.out.println("pre=" + ++count); // pre=3: 증가 후 사용
        count += 2; // 이 int 변수에서는 count = count + 2와 같은 결과
        System.out.println("sum=" + count); // sum=5
        System.out.println("division=" + 5 / 2 + ",remainder=" + 5 % 2); // division=2,remainder=1
        String result = count >= 3 ? "PASS" : "FAIL"; // if-else의 값 선택을 축약
        System.out.println(result); // PASS
        int number = 3;
        String selected = switch (number) {
            case 1 -> "ONE";
            case 2 -> "TWO";
            default -> "OTHER";
        };
        System.out.println(selected); // OTHER: 화살표 case는 다음 case로 이어지지 않음

        int rightCalls = 0;
        boolean left = false;
        boolean shortResult = left && (++rightCalls > 0);
        System.out.println("short=" + shortResult + ":" + rightCalls); // short=false:0
        boolean fullResult = left & (++rightCalls > 0);
        System.out.println("full=" + fullResult + ":" + rightCalls); // full=false:1

        for (int i = 1; i <= 5; i++) { // i++는 이 위치에서 i = i + 1
            if (i == 2) continue; // 2의 출력 생략
            if (i == 4) break; // 4에서 반복 종료
            System.out.println("for=" + i); // for=1, for=3
        }
        int runs = 0;
        boolean repeat = false;
        while (repeat) { runs++; }
        System.out.println("while=" + runs); // while=0
        do { runs++; } while (repeat); // 조건이 거짓이어도 한 번 실행
        System.out.println("do=" + runs); // do=1

        outer:
        for (int dan = 2; dan <= 4; dan++) {
            for (int n = 1; n <= 3; n++) {
                if (dan == 3) break outer; // 바깥 반복문까지 종료
                System.out.printf("%d*%d=%d%n", dan, n, dan * n);
                // 2*1=2, 2*2=4, 2*3=6이 줄별로 출력
            }
        }
    }
}
```

**따라 해보기**

1. 아래 명령을 실행하고 주석의 예상 출력과 비교한다.
2. `number`를 1과 2로 바꾸어 switch 결과를 비교한다.
3. `continue`와 `break` 줄을 한 줄씩 주석 처리하며 for 출력을 비교한다.
4. `break outer`를 `break`로 바꾸면 4단도 출력되는지 확인하고 복구한다.

```powershell

& "$jdk\java.exe" -cp . FlowPractice
```

**확인할 것**

- [ ] 후위 증감과 전위 증감이 각각 1과 3을 출력한다.
- [ ] 논리 연산에서 오른쪽 평가 횟수가 0과 1로 달라진다.

## Part 4. 문자열 비교와 조합

String은 내용을 변경할 수 없는 객체이다. 참조 비교와 내용 비교를 구분하고, 가변 버퍼에 내용을 추가하는 방법을 확인한다.

### 핵심 개념

| 기능 | 의미 |
| --- | --- |
| `==` | 같은 객체를 가리키는지 비교 |
| `String.equals()` | 문자열 내용 비교 |
| `length()` / `charAt()` | 길이 / 인덱스 위치의 문자 |
| `substring()` | 지정 범위의 문자열 반환 |
| `StringBuffer.append()` | 버퍼에 내용 추가 |

StringBuffer는 동기화된 메서드를 제공한다. StringBuilder는 동기화를 제공하지 않으며 단일 스레드의 문자열 조합에 적합하다. 이 실습에서는 수업에서 사용한 StringBuffer를 실행한다.

### Step 4-1. 같은 내용과 같은 객체 구별하기

리터럴로 만든 문자열과 `new String`으로 만든 문자열을 나란히 비교한다. 이후 문자열 메서드와 버퍼를 사용해 결과를 출력한다.

**목표**: 비교 기준과 문자열 메서드의 인덱스 규칙을 확인한다.

**사용 파일**: 출력할 문자열은 모두 영문자로 구성한다.

스터디 실습 가이드/실습/0812/StringPractice.java

```java
public class StringPractice {
    public static void main(String[] args) {
        String a = "AAA";
        String b = "AAA"; // 같은 리터럴 객체 공유
        String c = new String("AAA"); // 내용은 같고 객체는 새로 생성
        System.out.println(a == b); // true
        System.out.println(a == c); // false
        System.out.println(a.equals(c)); // true
        String text = "ABC";
        System.out.println(text.length()); // 3
        System.out.println(text.charAt(0)); // A: 인덱스는 0부터 시작
        System.out.println(text.substring(1, 3)); // BC: 끝 인덱스 3은 제외
        StringBuffer buffer = new StringBuffer();
        buffer.append("Java"); // 같은 버퍼에 Java 추가
        buffer.append(" Study"); // 이어서 공백과 Study 추가
        System.out.println(buffer.toString()); // Java Study: String으로 반환
    }
}
```

## Part 5. 숫자 맞추기로 입력·조건·반복 연결하기

숫자 맞추기는 입력값과 정답을 비교하면서 반복을 제어하는 실습이다. 작은 값에는 Up, 큰 값에는 Down을 출력하고 정답이면 즉시 끝낸다.

### 핵심 개념

- `Scanner`는 표준 입력에서 값을 읽는다. 정수인지 확인한 다음 읽어 잘못된 입력으로 프로그램이 중단되는 것을 막는다.
- 정답 범위는 1~100이며 반복은 최대 10회이다. 아래 복습 예제에서는 잘못된 입력도 한 번의 시도로 센다.
- `return`은 main 실행을 종료하고 `continue`는 현재 회차만 건너뛴다.
- 동작 확인에는 정답 42를 사용하고, 마지막에 수업의 난수 식으로 교체한다.

### Step 5-1. 성공과 실패 경로 실행하기

정답을 고정하면 같은 입력으로 힌트와 종료 조건을 재현할 수 있다. 동작을 확인한 뒤 난수를 사용해 실제 게임으로 바꾼다.

**목표**: 입력값 검증, Up·Down 분기, 정답 종료와 10회 제한을 구현한다.

**사용 파일**: 입력 처리는 아래 파일 안에 포함되어 있다.

스터디 실습 가이드/실습/0812/GuessGame.java

```java
import java.util.Scanner;

public class GuessGame {
    public static void main(String[] args) {
        int answer = 42; // 결과를 재현하기 위한 정답
        // 실제 게임에서는 위 줄을 다음 식으로 교체한다.
        // int answer = (int) (Math.random() * 100) + 1;
        final int maxTries = 10;
        try (Scanner scanner = new Scanner(System.in)) { // 종료 시 입력 자원 정리
            for (int tries = 1; tries <= maxTries; tries++) { // tries = tries + 1
                System.out.println("Try " + tries + ": enter 1-100");
                if (!scanner.hasNext()) { // 입력 자체가 끝나면 종료
                    System.out.println("Input ended.");
                    return;
                }
                if (!scanner.hasNextInt()) { // 다음 토큰이 정수인지 확인
                    scanner.next(); // 잘못된 토큰을 소비해 다음 입력으로 이동
                    System.out.println("Enter an integer.");
                    continue;
                }
                int guess = scanner.nextInt(); // 확인한 정수 읽기
                if (guess < 1 || guess > 100) {
                    System.out.println("Out of range.");
                    continue;
                }
                if (guess == answer) {
                    System.out.println("Success in " + tries + " tries. Answer: " + answer);
                    return; // 정답이면 이후 시도와 실패 출력을 실행하지 않음
                }
                System.out.println(guess < answer ? "Up" : "Down");
                // 10, 90, 42 입력: Up → Down → Success in 3 tries. Answer: 42
            }
            System.out.println("Failed. Answer: " + answer); // 10회 모두 실패했을 때
        }
    }
}
```

**따라 해보기**

1. 아래 명령으로 컴파일·실행하고 10, 90, 42를 차례로 입력한다.
2. 다시 실행해 1을 열 번 입력하고 실패 메시지와 시도 제한을 확인한다.
3. 다시 실행해 `abc`, `101`, `42`를 입력하고 입력 안내와 세 번째 시도의 성공을 확인한다.
4. `int answer = 42;`를 난수 식으로 교체한다. `Math.random()`은 0 이상 1 미만이고, 100을 곱해 정수로 변환한 뒤 1을 더하면 1~100이 된다.
5. 실행 기록을 비교할 때에는 정답을 다시 42로 복구한다.

```powershell

& "$jdk\java.exe" -cp . GuessGame
```

**확인할 것**

- [ ] 10에는 Up, 90에는 Down, 42에는 성공 메시지가 나온다.
- [ ] 성공 후 실패 메시지가 추가 출력되지 않는다.
- [ ] 10번 틀리면 정답을 포함한 실패 메시지가 나온다.
- [ ] 잘못된 입력과 범위 밖 입력에 안내가 출력되며 다음 시도로 진행한다.

**발표 포인트**: for를 while로 바꾸려면 시도 횟수의 초기화와 증가 위치를 직접 배치해야 한다. 특히 continue 경로에서도 횟수가 증가하는지 확인한다.

### 제목 비교가 문자열 생성 방식에 따라 달라짐

**증상**: 블로그의 `==`·`!=` 비교를 새 문자열 객체에 적용하면 내용 비교와 다른 결과가 나온다.

**원인**: 참조 타입의 `==`와 `!=`는 같은 객체를 가리키는지 비교한다.

**해결**: `"title1".equals(title)`과 `!"title2".equals(request.getTitle())`로 비교한다. 두 번째 조건의 부정 의미도 유지한다. Step 1-1에서 결과 차이를 재현한다.
