## Part 1. 변수 선언과 실행

지역 변수는 메서드 안에서 값을 저장하고 사용한다. main에서 선언한 값이 콘솔에 표시되는 과정을 확인한다.

### 핵심 개념

#### JDK·JRE·JVM과 실행 과정

Java 프로그램은 소스를 컴파일한 뒤 JVM에서 실행한다. 개발 도구와 실행 환경, 실제 실행을 담당하는 가상 머신의 역할을 구분한다.

| 구분 | 이름 | 역할 | 수업 코드와의 연결 |
| --- | --- | --- | --- |
| JDK | Java Development Kit | 컴파일러 등 개발 도구와 실행에 필요한 구성 요소를 제공하는 개발 키트 | JDK 17의 `javac`로 소스를 컴파일하고 `java`로 실행 |
| JRE | Java Runtime Environment | JVM과 표준 라이브러리 등 프로그램 실행에 필요한 환경 | 프로그램이 사용하는 실행 기반. 컴파일러는 개발 도구에 해당 |
| JVM | Java Virtual Machine | 바이트코드를 실행하고 메모리와 객체의 생명주기를 관리하는 가상 머신 | 컴파일된 `VariableApp.class`의 코드를 실행 |

역할을 기준으로 보면 **JDK는 개발 도구와 실행 환경을 제공하고, JRE는 JVM과 실행 라이브러리를 포함한다.** 이는 구성 요소의 개념적 관계이며, 설치 폴더가 항상 `JDK → JRE → JVM` 형태로 중첩된다는 뜻은 아니다. 이번 실습은 설치된 JDK 17을 사용한다.

실행 흐름은 **`VariableApp.java` → `javac`로 컴파일 → `VariableApp.class` → `java`로 JVM 시작 → `main` 실행**이다. 컴파일 결과는 JVM이 이해하는 바이트코드이며, 실행 환경에 맞는 JVM이 이를 실행한다.

#### Java 기본 타입 8종

기본 타입 변수에는 해당 타입의 값을 저장한다. 정수·실수·문자·논리를 표현하는 기본 타입은 아래 8종이며, `String`은 객체를 가리키는 참조 타입이다.

| 분류 | 기본 타입 | 래퍼 클래스 | 값의 비트 수 | 표현 범위 또는 특징 | 선언 예시 |
| --- | --- | --- | --- | --- | --- |
| 정수 | `byte` | `Byte` | 8비트 | -128~127 | `byte level = 10;` |
| 정수 | `short` | `Short` | 16비트 | -32,768~32,767 | `short count = 1000;` |
| 정수 | `int` | `Integer` | 32비트 | -2³¹~2³¹-1, 일반적인 정수 계산 | `int age = 27;` |
| 정수 | `long` | `Long` | 64비트 | -2⁶³~2⁶³-1, 큰 정수. 리터럴에 `L` 사용 | `long total = 3000000000L;` |
| 실수 | `float` | `Float` | 32비트 | 단정밀도 부동소수점, 십진수 약 6~7자리 정밀도. 리터럴에 `F` 사용 | `float rate = 1.5F;` |
| 실수 | `double` | `Double` | 64비트 | 배정밀도 부동소수점, 십진수 약 15~16자리 정밀도 | `double price = 3.14;` |
| 문자 | `char` | `Character` | 16비트 | 0~65,535의 UTF-16 코드 단위. 작은따옴표 사용 | `char gender = 'm';` |
| 논리 | `boolean` | `Boolean` | 고정 저장 크기를 규정하지 않음 | `true` 또는 `false` | `boolean isMarried = false;` |

표의 비트 수는 타입이 표현하는 값의 폭이며 객체 전체의 메모리 사용량을 뜻하지 않는다. `char` 하나는 UTF-16 코드 단위 하나이므로 모든 문자를 하나의 `char`에 담을 수 있는 것은 아니다. 부동소수점은 일부 소수를 근삿값으로 표현한다.

`VariableApp`의 `age`, `gender`, `isMarried`는 기본 타입이고 `name`은 `String` 참조 타입이다. 이 변수들은 모두 `main` 안의 지역 변수이므로 읽기 전에 초기화한다. 클래스의 필드에는 타입에 따라 `0`, `0.0`, `'\u0000'`, `false`, `null` 등의 기본값이 부여된다.

#### 래퍼 클래스

래퍼 클래스는 기본 타입의 값을 객체로 다룰 때 사용한다. 컬렉션처럼 객체 타입을 요구하는 곳에 값을 저장하거나, 문자열을 숫자로 변환하는 메서드를 사용할 때 필요하다. 래퍼 변수는 참조 타입이므로 `null`을 저장할 수 있지만, 이를 기본 타입으로 꺼낼 때에는 `NullPointerException`이 발생할 수 있다.

```java
Integer count = Integer.valueOf(10); // int 값 10을 나타내는 Integer 객체 반환
int parsed = Integer.parseInt("20"); // 문자열을 int 20으로 변환
System.out.println(count + parsed);  // 30
```

#### 캐스팅

캐스팅은 값을 다른 타입으로 변환하는 것이다. 표현 범위가 작은 정수 타입에서 큰 타입으로 옮기는 확대 변환은 자동으로 처리될 수 있다. 큰 범위에서 작은 범위로 옮기는 축소 변환은 타입을 명시해야 하며, 값이 대상 타입의 범위를 벗어나면 정보가 손실될 수 있다. 실수를 정수로 바꾸면 소수 부분이 제거된다.

```java
int number = 10;
long widened = number;       // int에서 long으로 자동 확대 변환
double decimal = widened;    // long에서 double로 자동 변환
int truncated = (int) 3.8;   // 명시적 축소 변환: 소수 부분이 제거되어 3
byte overflow = (byte) 130;  // byte 범위를 넘어 결과는 -126
System.out.println(truncated); // 3
System.out.println(overflow);  // -126
```

#### 박싱과 언박싱

박싱은 기본 타입 값을 대응하는 래퍼 클래스 객체로 변환하는 과정이고, 언박싱은 래퍼 객체에서 기본 타입 값을 꺼내는 과정이다. 대입문에서 컴파일러가 이를 자동으로 처리하면 오토박싱과 오토언박싱이라고 한다.

```java
int score = 90;
Integer boxed = score; // 오토박싱: int → Integer
int unboxed = boxed;   // 오토언박싱: Integer → int
System.out.println(unboxed); // 90

Integer nullable = null;
// int value = nullable; // 실행하면 null을 언박싱하므로 NullPointerException 발생
```

래퍼 객체의 값을 비교할 때에는 객체의 동일성보다 값의 비교가 목적이다. 숫자 비교는 언박싱한 기본 타입이나 `equals()`를 사용한다. `Integer`의 `==` 결과는 객체 캐시 등의 영향을 받을 수 있으므로 값 비교 방법으로 의존하지 않는다.

Teacher는 상태를 필드에 담고 메서드로 값을 읽거나 변경한다. TeacherApp에서 new로 객체를 만들고 접근하는 순서를 관찰한다.

```java
// 가이드 설명: get 메서드는 해당 필드를 반환하고 set 메서드는 매개변수 값을 필드에 대입한다.
package features.var;

public class Teacher {
    // 선언 위치가 클래스 블럭 -> 멤버변수
    public String name;
    public int age;
    public char gender;
    public String job;

    public String getName() {
        return name;
    }
    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }
    public void setAge(int age) {
        this.age = age;
    }

    public char getGender() {
        return gender;
    }
    public void setGender(char gender) {
        this.gender = gender;
    }

    public String getJob() {
        return job;
    }
    public void setJob(String job) {
        this.job = job;
    }
}
```

be/javaPractice/src/TeacherApp.java

```java
// 가이드 설명: main은 객체를 만들고 이름과 직업을 설정·조회한다. 객체 표기 다음에 김영석, 화학 선생님이 출력된다. 객체 표기의 @ 뒤 값은 실행마다 다를 수 있다.
import features.var.Teacher;

public class TeacherApp {
    public static void main(String[] args) {
        // new 연산자로 instance 생성 가능
        Teacher teacher = new Teacher();
        System.out.println("teacher = " + teacher);

        // 인스턴스의 메서드 접근
        teacher.setName("김영석");
        String name = teacher.getName();
        System.out.println(name);

        // 인스턴스의 변수 접근
        teacher.job = "화학 선생님";
        String job = teacher.getJob();
        System.out.println(job);
    }
}
```

## Part 4. Lombok과 DTO 생성

DTO(Data Transfer Object)는 여러 값을 하나의 객체로 묶어 계층이나 메서드 사이에 전달할 때 사용하는 객체이다. `BlogRequestDTO`는 블로그 요청에 필요한 `id`, `title`, `content`, `email`을 하나로 묶어 전달한다. 이렇게 하면 값을 각각 전달하는 것보다 매개변수의 의미를 파악하기 쉽고, 전달할 값이 늘어날 때 메서드 매개변수 목록이 계속 길어지는 것을 줄일 수 있다.

DTO는 데이터를 전달하는 역할에 집중한다. 이 수업의 `BlogRequestDTO`도 데이터를 저장하는 필드와 생성·조회·변경 기능으로 구성되며, 업무 처리 로직은 포함하지 않는다. DTO가 데이터베이스 테이블과 직접 연결된다는 의미는 아니며, Entity처럼 식별성과 영속 상태를 표현하는 객체와 역할이 다르다.

| 구분 | 역할 | 이 실습의 예 |
| --- | --- | --- |
| 개별 값 전달 | 값을 매개변수별로 전달하며 순서와 개수를 맞춤 | `register(title, content, email)` 형태 |
| 요청 DTO | 관련 입력값을 하나의 객체로 묶어 전달 | `BlogRequestDTO` |
| Entity | 식별성을 가진 도메인 객체이며 영속성 기술에서 테이블과 연결될 수 있음 | 이 날짜의 실습 코드에는 없음 |

Lombok은 반복해서 작성하는 생성자와 getter·setter 같은 코드를 어노테이션에 따라 컴파일 과정에서 생성한다. 소스 파일에는 메서드가 직접 보이지 않아도 어노테이션 처리가 정상적으로 이루어지면 컴파일된 클래스에서 사용할 수 있다. 따라서 컴파일할 때 `lombok.jar`를 클래스 경로와 어노테이션 처리기 경로에 포함해야 한다.

### 핵심 개념

| 어노테이션 | 생성 기능 | 커밋 코드에서 사용하는 결과 |
| --- | --- | --- |
| `@Getter` | 각 필드의 조회 메서드 | `request3.getContent()` |
| `@Setter` | 각 필드의 변경 메서드 | `request3.setEmail("AAA@gmail.com")` |
| `@NoArgsConstructor` | 매개변수가 없는 생성자 | `new BlogRequestDTO()` |
| `@AllArgsConstructor` | 선언된 필드를 순서대로 받는 전체 인자 생성자 | `new BlogRequestDTO(1, "", "", "")` |
| `@Builder` | 필드 이름으로 값을 지정하고 객체를 생성하는 Builder | `BlogRequestDTO.builder().title("ABC").build()` |

생성 방법에 따라 값을 지정하는 방식도 달라진다.

| 생성 방법 | 특징 | 주의점 |
| --- | --- | --- |
| 무인자 생성자 | 빈 객체를 만든 뒤 setter로 값을 입력 | 필드를 설정하지 않으면 참조 타입 필드는 `null` |
| 전체 인자 생성자 | 한 번의 호출로 모든 필드를 입력 | 선언된 필드의 개수·타입·순서를 맞춰야 함 |
| Builder | 필드 이름을 보면서 필요한 값만 지정 | 생략한 참조 타입 필드는 별도 기본값 설정이 없으면 `null` |

이 코드에는 `@Setter`가 있으므로 생성 이후에도 DTO 값을 바꿀 수 있다. `@Builder`를 사용했다고 객체가 자동으로 불변 객체가 되는 것은 아니다. 불변 객체가 필요하다면 setter 제공 여부와 필드 선언, 생성 방식을 함께 설계해야 한다.

```java
// 가이드 설명: 필드 순서는 id, title, content, email이다. getter·setter 생성과 Builder 생성은 서로 다른 어노테이션의 역할이다.
package features.blogs.domain.dto;

import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

@Builder
@NoArgsConstructor
@AllArgsConstructor
@Setter
@Getter

public class BlogRequestDTO {
    private Integer id;
    private String title;
    private String content;
    private String email;
}
```
