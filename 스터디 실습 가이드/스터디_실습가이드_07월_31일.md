## Part 1. Promise와 Fetch

Promise는 완료 시점을 바로 알 수 없는 작업의 상태와 결과를 나타내고, Fetch는 이 Promise를 이용해 데이터를 요청하는 브라우저 API다. 이 Part에서는 비동기 작업의 성공·실패 상태를 먼저 관찰한 뒤, 응답을 기다리고 JSON 본문을 JavaScript 데이터로 변환하는 순서를 익힌다.

### 핵심 개념

| 처리 단계 | Promise 상태 | Result |
| --- | --- | --- |
| 작업 진행 중 | Pending | `undefined` |
| `resolve(value)` 호출 | Fulfilled | `value` |
| `reject(error)` 호출 | Rejected | `error` |

Fulfilled와 Rejected는 모두 처리가 끝난 Settled 상태다. `.then()`은 성공 결과를, `.catch()`는 실패를 처리하며, `.then()`도 Promise를 반환하므로 후속 동작을 체인으로 연결할 수 있다.

### Step 1-1. Promise 상태 변화 관찰

`new Promise()`에는 작업을 수행할 함수가 전달되며, 그 안에서 `resolve()` 또는 `reject()`를 호출하면 대기 중이던 작업의 결과가 결정된다. 지연 시간을 둔 예제로 상태가 즉시 끝나지 않는다는 점과 성공·실패 후속 처리의 차이를 확인한다.

**목표**: 지연된 비동기 작업이 Pending에서 Fulfilled 또는 Rejected로 바뀌는 과정을 확인한다.

**사용 파일**

`fe/front/html/scriptPromise.html`

```javascript
// 1. resolve와 reject를 전달받아 비동기 작업의 성공·실패를 결정한다.
const promise = new Promise((resolve, reject) => {
    // 2. 5초 지연으로 서버 응답처럼 즉시 끝나지 않는 작업을 재현한다.
    setTimeout(() => {
        // resolve()를 실행하면 Promise는 Fulfilled가 되고 이 객체가 결과가 된다.
        resolve({ status: 200, data: { message: "success" } });
        // reject()를 대신 실행하면 Promise는 Rejected가 되고 .catch()로 전달된다.
        // reject({ status: 404 });
    }, 5000);
});

// 3. 성공 결과는 .then(), 실패 결과는 .catch()가 처리한다.
promise
    .then(response => {
        // Console(5초 뒤): response = { status: 200, data: { message: "success" } }
        console.log("response =", response);
    })
    .catch(error => {
        // reject({ status: 404 })를 활성화했을 때 Console: error = { status: 404 }
        console.log("error =", error);
    });
```

**따라 해보기**

1. 파일의 Promise 예제 주석을 해제하고 `scriptPromise.html`을 연다.
2. 페이지를 새로고침한 직후와 5초 뒤 Console에서 `promise`의 상태를 비교한다.
3. `resolve()`를 주석 처리하고 `reject()`를 활성화해 다시 실행한다.
4. 성공은 `.then()`, 실패는 `.catch()`에서 처리되는지 확인한다.

**확인할 것**

- [ ] 처음에는 Pending 상태인가?
- [ ] `resolve()` 후 Fulfilled와 성공 데이터가 확인되는가?
- [ ] `reject()` 후 Rejected와 오류 데이터가 `.catch()`로 전달되는가?

**발표 포인트**

Promise는 완료된 값 자체가 아니라 미래에 결정될 작업의 상태와 결과를 관리한다.

**예상 질문 & 답변**

- **Q. `.then()` 뒤에 `.catch()`를 계속 연결할 수 있는 이유는 무엇인가?**
  - A. `.then()`이 다시 Promise를 반환하기 때문에 후속 처리를 체인으로 연결할 수 있다.

### Step 1-2. Fetch로 로컬 JSON 읽기

`fetch()`가 완료되면 곧바로 배열이 아니라 상태·헤더·본문 정보를 가진 `Response` 객체를 받는다. 실제 사용자 배열을 얻으려면 `response.json()`도 기다려야 하므로, 버튼 핸들러를 `async` 함수로 만들고 두 단계에 각각 `await`를 사용한다.

**목표**: Fetch의 `Response` 객체와 JSON 본문 변환을 각각 기다려 실제 배열을 얻는다.

**사용 파일**

`fe/front/html/scriptPromise.html`

`fe/front/server/users.json`

`fe/front/html/scriptPromise.html`

```javascript
// 1. 버튼을 클릭하면 async 이벤트 핸들러가 실행된다.
document.querySelector("#btn").onclick = async () => {
    try {
        // 2. JSON 파일 요청이 끝날 때까지 기다려 Response 객체를 받는다.
        const response = await fetch("../server/users.json");

        // 3. 응답 본문을 JavaScript 배열로 변환하는 작업도 기다린다.
        // response.json() 결과: users.json의 사용자 객체 5개를 담은 배열
        const data = await response.json();

        // 4. 변환이 끝난 배열의 사용자 객체를 인덱스와 함께 출력한다.
        // Console: 0부터 4까지의 인덱스와 각 사용자 객체가 차례로 출력된다.
        data.forEach((obj, index) => {
            console.log(index, obj);
        });
    } catch (error) {
        // 요청 또는 본문 변환 과정에서 발생한 오류를 확인한다.
        console.log("error =", error);
    }
};
```

2. Network 패널에서 `users.json` 요청을 선택해 응답 본문을 확인한다.
3. Console에서 다섯 사용자 객체가 인덱스와 함께 출력되는지 확인한다.
4. `await response.json()`에서 `await`를 제거해 `data`가 즉시 사용할 배열인지 비교한 뒤 되돌린다.

## Part 2. 서버 데이터로 동적 카드 만들기

서버에서 받은 배열은 그대로는 화면 요소가 아니므로, 각 객체를 DOM 요소로 바꾸고 부모 요소에 연결해야 한다. 이 Part에서는 사용자 배열을 화면의 원본 데이터로 두고 카드를 생성하며, 배열이 바뀌면 현재 데이터 기준으로 DOM을 다시 만들어 두 상태를 맞춘다.

### 핵심 개념

| 문법 | 역할 |
| --- | --- |
| `document.createElement()` | 새 DOM 요소 생성 |
| `className` | 생성한 요소에 CSS 클래스 지정 |
| `textContent` | 요소의 텍스트 설정 |
| `appendChild()` | 부모 요소에 자식 요소 연결 |
| `?.` | 중간 객체가 없을 때 오류 대신 `undefined` 반환 |
| `??` | 값이 `null` 또는 `undefined`일 때 기본값 사용 |
| `container.innerHTML = ""` | 재렌더링 전에 기존 자식 요소 제거 |

### Step 2-1. 사용자 배열을 카드 DOM으로 변환

데이터 로딩과 화면 생성을 별도 함수로 나누면 “데이터를 먼저 받기 → 카드 만들기” 순서를 분명히 할 수 있다. 각 사용자 객체에서 필요한 값을 꺼내 요소의 텍스트와 속성을 채우고, 삭제 시에는 배열부터 수정한 뒤 카드 목록을 다시 렌더링한다.

**목표**: 원격 사용자 배열의 각 객체를 카드 요소로 만들어 화면에 출력한다.

**사용 파일**

`fe/front/html/scriptDOMCreate.html`

`fe/front/css/create.css`

`fe/front/html/scriptDOMCreate.html`

```javascript
// 서버에서 받은 사용자 배열을 보관하는 화면 데이터다.
let data = [];

// 1. 사용자 데이터를 요청하고 JSON 배열로 변환한다.
const loadData = async () => {
    try {
        // fetch() 결과: HTTP 응답 정보를 담은 Response 객체
        const response = await fetch("https://fakestoreapi.com/users");
        // response.json() 결과: API가 반환한 사용자 객체 배열
        data = await response.json();
    } catch (error) {
        // 통신 또는 JSON 변환 오류를 Console에서 확인한다.
        console.log(error);
    }
};

// 2. 현재 data 배열을 기준으로 카드 목록을 만든다.
const makeCard = () => {
    // 다시 렌더링할 때 이전 카드가 중복되지 않도록 부모 요소를 먼저 비운다.
    container.innerHTML = "";

    data.forEach((obj, index) => {
        // 사용자 한 명을 담을 카드 요소를 생성하고 CSS 클래스를 지정한다.
        const card = document.createElement("div");
        card.className = "card";

        // 사용자 이름을 h3 요소의 텍스트로 설정한다.
        const name = document.createElement("h3");
        name.textContent = obj.username;

        // 이메일을 p 요소의 텍스트로 설정한다.
        const email = document.createElement("p");
        email.textContent = obj.email;

        // address가 있으면 city를 읽고, 결과가 null 또는 undefined면 "N/A"를 사용한다.
        const city = document.createElement("p");
        city.textContent = obj.address?.city ?? "N/A";

        // 삭제 버튼은 현재 index의 배열 항목을 지운 뒤 화면을 다시 만든다.
        const delBtn = document.createElement("button");
        delBtn.className = "btn";
        delBtn.textContent = "삭제하기";
        delBtn.addEventListener("click", () => {
            // splice(index, 1)의 반환값은 제거된 사용자 배열이고, data에서는 해당 사용자 한 명이 빠진다.
            data.splice(index, 1);
            // 화면 결과: 제거된 사용자를 제외한 카드 목록이 다시 표시된다.
            makeCard();
        });

        // 3. 내용을 카드에 넣고, 완성된 카드를 목록 컨테이너에 연결한다.
        card.appendChild(name);
        card.appendChild(email);
        card.appendChild(city);
        card.appendChild(delBtn);
        container.appendChild(card);
    });
};

// 4. 데이터 로딩이 끝난 뒤에만 카드 렌더링을 시작한다.
const init = async () => {
    await loadData();
    makeCard();
};

// 5. 페이지에서 전체 비동기 흐름을 시작한다.
init();
```

**따라 해보기**

1. `scriptDOMCreate.html`을 열고 사용자 카드가 생성되는지 확인한다.
2. Elements 패널에서 각 카드가 `.card` 클래스를 가진 `div`인지 확인한다.
3. 삭제하기 버튼을 눌러 배열에서 한 항목이 제거되고 카드 목록이 다시 그려지는지 확인한다.
4. `container.innerHTML = ""`를 잠시 주석 처리하고 삭제 버튼을 눌러 중복 렌더링을 재현한 뒤 되돌린다.
5. 도시 출력식을 `obj.address?.city ?? "N/A"`로 유지한 채 `address`가 없는 임시 객체를 배열에 넣어 기본값을 확인한다.

**확인할 것**

- [ ] 서버 응답이 도착한 뒤에만 `makeCard()`가 실행되는가?
- [ ] `createElement()`로 만든 요소가 부모·자식 구조로 연결되는가?
- [ ] 삭제 후 기존 DOM을 비우고 현재 배열 기준으로 다시 렌더링하는가?
- [ ] 중첩 값이 없을 때 `N/A`가 표시되는가?

**발표 포인트**

데이터 배열이 원본 상태이고, 화면은 배열을 기준으로 다시 만든 결과라는 흐름을 강조한다.

**예상 질문 & 답변**

- **Q. 삭제 버튼을 누른 뒤 카드 요소 하나만 직접 지우지 않고 왜 `makeCard()`를 다시 호출하는가?**
  - A. 변경된 배열을 기준으로 화면 전체를 다시 만들어 데이터와 DOM의 상태를 일치시키기 위해서다.

## Part 3. Axios와 HTTP 요청 설계

Axios는 Fetch와 마찬가지로 Promise 기반으로 HTTP 요청을 보내지만, 변환된 JSON 데이터를 응답 객체의 `data`에서 바로 제공한다. 이 Part에서는 같은 조회 요청의 응답 처리 차이를 비교하고, 데이터 생성·조회·수정·삭제 목적에 맞는 HTTP 메서드를 연결한다.

### 핵심 개념

| 항목 | Fetch API | Axios |
| --- | --- | --- |
| 제공 방식 | 브라우저 내장 | 외부 HTTP 라이브러리 |
| 요청 결과 | `Response` 객체 | Axios 응답 객체 |
| JSON 데이터 | `await response.json()` 필요 | `response.data`에서 바로 접근 |
| 공통점 | Promise와 `async/await` 사용 | Promise와 `async/await` 사용 |

| CRUD | HTTP 메서드 | 역할과 일반적인 데이터 위치 |
| --- | --- | --- |
| Create | POST | 새 데이터를 요청 본문에 전달 |
| Read | GET | 조회 조건을 쿼리스트링 또는 `params`로 전달 |
| Update | PUT | 리소스 전체를 요청 본문으로 교체 |
| Update | PATCH | 리소스 일부를 요청 본문으로 수정 |
| Delete | DELETE | 대상 ID를 URL 경로로 전달 |

JWT 같은 인증 토큰은 일반 데이터와 분리해 HTTP 헤더로 전달한다.

### Step 3-1. Axios로 상품 목록 출력

HTML에서 Axios를 사용하려면 먼저 CDN 스크립트를 불러와 `axios` 객체를 준비한다. 상품 GET 요청이 끝난 뒤 `response.data`의 배열을 순회하여 이미지·제목·가격 요소를 만들고 카드 목록에 연결한다.

**목표**: Axios 응답의 `data`를 읽고 상품 이미지·제목·가격 카드를 만든다.

**사용 파일**

`fe/front/html/scriptAxios.html`

`fe/front/css/axios.css`

`fe/front/html/scriptAxios.html`

```html
<!-- 아래 JavaScript보다 먼저 Axios 라이브러리를 불러와 axios 객체를 준비한다. -->
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
```

`fe/front/html/scriptAxios.html`

```javascript
// Axios 응답에서 꺼낸 상품 배열을 보관한다.
let data;

// 1. GET 요청이 끝날 때까지 기다린 뒤 파싱된 배열을 response.data에서 읽는다.
const loadData = async () => {
    // axios.get() 결과: 상태·헤더·data 등을 가진 Axios 응답 객체
    const response = await axios.get(
        "https://fakestoreapi.com/products"
    );
    // response.data 결과: API가 반환한 상품 객체 배열
    data = response.data;
};

// 2. 상품 객체마다 이미지·제목·가격 요소를 가진 카드를 만든다.
const makeProduct = () => {
    // 화면 결과: data의 상품 수만큼 이미지·제목·가격 카드가 생성된다.
    data.forEach(obj => {
        const card = document.createElement("div");
        card.className = "card";

        // 원격 이미지 주소를 img 요소의 src에 설정한다.
        const image = document.createElement("img");
        image.src = obj.image;
        image.width = "200";

        // 상품 제목과 가격은 textContent로 넣는다.
        const title = document.createElement("h3");
        title.textContent = obj.title;

        const price = document.createElement("p");
        price.textContent = obj.price;

        card.appendChild(image);
        card.appendChild(title);
        card.appendChild(price);
        container.appendChild(card);
        // appendChild() 결과: image → title → price 순서의 카드가 container 끝에 추가된다.
    });
};

// 3. 상품 배열을 모두 받은 다음 카드 생성을 시작한다.
const init = async () => {
    await loadData();
    makeProduct();
};

// 4. 페이지에서 전체 비동기 흐름을 시작한다.
init();
```

3. Console에서 `response`와 `response.data`를 각각 출력해 구조를 비교한다.

## Part 4. Flexbox와 미디어 쿼리

Flexbox는 여러 카드의 배치와 간격 및 줄바꿈을 한 컨테이너에서 제어하고, 미디어 쿼리는 화면 너비 조건에 따라 다른 CSS를 적용한다. 이 Part에서는 같은 카드 목록이 공간에 맞춰 배치되는 과정과 모바일·태블릿·데스크톱 경계에서 스타일이 전환되는 과정을 확인한다.

### 핵심 개념

| CSS | 역할 |
| --- | --- |
| `display: flex` | 자식 요소를 유연한 축으로 배치 |
| `gap` | 행과 열 사이 간격 설정 |
| `flex-wrap: wrap` | 공간이 부족하면 다음 줄로 이동 |
| `@media` | 화면 조건에 맞는 CSS만 적용 |

### Step 4-1. 카드 목록을 Flexbox로 배치

카드의 부모 요소를 Flex 컨테이너로 만들면 자식 카드가 가로 방향으로 배치된다. 카드 폭의 합이 화면보다 커질 때 `flex-wrap`으로 다음 줄에 배치하고, `gap`으로 카드 사이의 간격을 일정하게 유지한다.

**목표**: 카드가 화면 너비에 맞춰 가로로 배치되고 자동 줄바꿈되게 한다.

**사용 파일**

`fe/front/css/create.css`

```css
/* 1. 카드의 부모를 Flex 컨테이너로 만들고 간격과 자동 줄바꿈을 적용한다. */
.container {
    display: flex;
    gap: 20px;
    flex-wrap: wrap;
}

/* 2. 각 카드의 크기와 테두리 및 움직임의 전환 시간을 지정한다. */
.card {
    border: 1px solid yellowgreen;
    border-radius: 10px;
    width: 220px;
    padding: 15px;
    transition: transform 200ms;
}

/* 3. 마우스를 올리면 카드가 위로 3px 이동하고 transition으로 부드럽게 보인다. */
.card:hover {
    transform: translateY(-3px);
}
```

### Step 4-2. 화면 너비별 스타일 적용

미디어 쿼리는 조건에 맞는 화면 너비에서만 내부 CSS를 적용한다. 서로 이어지는 경계값을 직접 확인하면 어느 구간에서도 규칙이 겹치거나 비지 않는지 검증할 수 있다.

        background: url("../img/bg.jpg") no-repeat;

        justify-content: center;
        align-items: center;
        height: 100vw;
    }
}

/* 3. 1024px 이상에서는 데스크톱용 배경 규칙을 적용한다. */

    body {

    }
}

## Part 5. 선택자와 이벤트 토글

CSS 선택자는 꾸밀 요소의 범위를 정하고, 이벤트 핸들러는 사용자의 클릭에 맞춰 화면 값을 바꾼다. 이 Part에서는 직계 자식과 모든 후손을 선택하는 범위를 비교한 뒤, 하나의 불리언 상태로 제목·이미지·버튼 문구가 함께 전환되도록 구현한다.

### 핵심 개념

| 선택자·프로퍼티 | 역할 |
| --- | --- |
| `parent > child` | 바로 아래 직계 자식만 선택 |
| `parent child` | 깊이에 관계없이 모든 후손 선택 |
| `event.target` | 이벤트가 실제로 발생한 요소 |
| `textContent` | 요소의 문구 변경 |
| `src` | 이미지 경로 변경 |

### Step 5-1. 커피 카드 상태 전환

**목표**: 불리언 상태를 기준으로 제목·이미지·버튼 문구를 한 번에 토글한다.

        isBlue = true;

});

## 트러블슈팅 케이스

### Promise를 배열처럼 순회할 수 없음

**증상**

`data.forEach is not a function`이 발생하거나 데이터가 채워지기 전에 카드 렌더링이 실행된다.

**원인**

`fetch()`와 `response.json()`이 반환한 Promise의 완료를 기다리지 않고 결과를 배열처럼 사용했다.

**해결**

`fe/front/html/scriptDOMCreate.html`

```javascript
// 두 Promise가 끝난 뒤에야 data를 배열로 사용하고 카드를 만든다.
const response = await fetch("https://fakestoreapi.com/users");
data = await response.json(); // 결과: API가 반환한 사용자 객체 배열
makeCard(); // 화면 결과: 사용자 배열의 각 객체가 카드로 표시된다.
```

### 스타일시트가 적용되지 않음

**증상**

`scriptPromise.html`에 연결한 `create.css`가 적용되지 않는다.

**원인**

`<link>` 태그에 `rel`이 아니라 `ref="stylesheet"`가 작성되어 있다.

**해결**

`fe/front/html/scriptPromise.html`

```html
<!-- rel="stylesheet"로 이 링크가 CSS 스타일시트임을 브라우저에 알린다. -->
<link href="../css/create.css" rel="stylesheet">
```

### 데스크톱 미디어 쿼리가 완성되지 않음

**증상**

`media.css` 마지막 규칙의 중괄호 구조가 맞지 않는다.

**원인**

`@media`와 내부 `body` 블록을 열었지만 닫는 중괄호가 하나만 있다.

**해결**

`fe/front/css/media.css`

```css
/* body 블록과 @media 블록을 각각 닫아 규칙을 완성한다. */
@media screen and (min-width: 1024px) {
    body {
        background: url("../img/bg.jpg") no-repeat;
    }
}
```
