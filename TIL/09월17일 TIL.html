  • 외부 해수욕장 예보 API를 호출하고 응답을 가공해 React 화면에 표시하는 흐름을 구현했다.

오늘 배운 것

모놀리식 아키텍처와 MSA 비교

모놀리식 아키텍처는 여러 기능이 하나의 애플리케이션에 모여 있어 개발 초기에 구조를 이해하고 실행하기 쉽다. 반면 한 부분의 장애나 배포가 전체 애플리케이션에 영향을 줄 수 있고, 특정 기능만 따로 확장하기 어렵다.

MSA는 기능을 독립적인 서비스로 분리한다. 각 서비스를 개별적으로 배포하고 필요한 서비스만 확장할 수 있지만, 서비스 간 통신과 데이터 일관성 관리가 추가되어 전체 시스템 운영은 더 복잡해진다.

구분 모놀리식 MSA
구성 여러 기능이 하나의 애플리케이션에 포함된다. 기능별 서비스가 독립적으로 구성된다.
배포 전체 애플리케이션을 함께 배포한다. 서비스별로 독립 배포할 수 있다.
확장 대체로 전체 애플리케이션 단위로 확장한다. 부하가 큰 서비스만 선택적으로 확장할 수 있다.
장애 영향 한 기능의 장애가 전체 서비스에 영향을 줄 가능성이 크다. 서비스가 분리되어 장애 범위를 제한하기 쉽다.
데이터 관리 하나의 데이터베이스 트랜잭션으로 관리하기 쉽다. 서비스별 데이터가 분리되면 분산 트랜잭션과 데이터 일관성 관리가 어렵다.

서비스 통신과 서비스 디스커버리

MSA에서는 서비스가 서로 다른 프로세스나 서버에서 실행될 수 있으므로 네트워크를 통해 통신한다. 즉시 응답이 필요하면 HTTP나 gRPC 같은 동기 방식을 사용할 수 있고, 느슨한 결합과 안정적인 이벤트 처리가 중요하면 메시지 큐를 이용한 비동기 방식을 사용할 수 있다.

Service Discovery는 실행 중인 서비스의 주소와 상태를 관리하고 필요한 서비스의 위치를 찾게 해 준다. Netflix의 Eureka Server가 대표적인 구현이지만, 모든 MSA가 별도의 디스커버리 서버를 반드시 사용하는 것은 아니며 배포 환경에 따라 다른 방식을 선택할 수 있다.

API 게이트웨이와 Spring Cloud

API Gateway는 클라이언트가 여러 내부 서비스에 직접 접근하지 않도록 외부 요청을 받는 단일 진입점 역할을 한다. 요청 경로에 맞는 서비스로 트래픽을 전달하므로 외부와 내부 서비스의 구조를 분리할 수 있다.

Spring Cloud는 Spring Boot 애플리케이션에서 설정 관리, 서비스 탐색, 게이트웨이 같은 분산 시스템 기능을 구현하도록 돕는다. Spring Cloud 자체가 클러스터는 아니며, MSA 구축에 활용할 수 있는 프레임워크와 라이브러리의 모음이다.

외부 API 요청과 응답 처리

외부 API를 호출할 때는 명세에 맞는 엔드포인트와 쿼리 파라미터를 정확하게 조합해야 한다. UriComponentsBuilder로 요청 URL을 만들고 HttpURLConnection으로 연결한 뒤, 상태 코드가 성공일 때 응답 스트림을 읽을 수 있다.

// 쿼리 파라미터를 URI에 추가한 뒤 외부 API를 호출한다.
String requestUrl = UriComponentsBuilder.fromUriString(endpoint)
    .queryParam("date", date)
    .build()
    .toUriString();

HttpURLConnection connection =
    (HttpURLConnection) new URL(requestUrl).openConnection();

// 상태 코드가 200이면 응답 본문을 읽을 수 있다.
if (connection.getResponseCode() == 200) {
    InputStream stream = connection.getInputStream();
}

JSON 파싱과 열거형을 이용한 값 변환

ObjectMapper.readTree()는 JSON을 JsonNode 트리로 만들며, 필요한 배열 노드를 DTO 배열로 변환할 수 있다. 외부 API의 짧은 코드와 숫자값은 enum에 이름, 단위, 변환 규칙을 모아 두면 응답을 화면 친화적인 값으로 바꾸기 쉽다.

// JSON 배열을 DTO 배열로 변환한다.
JsonNode root = objectMapper.readTree(json);
JsonNode items = root.findValue("item");
List<ResponseDto> responses =
    Arrays.asList(objectMapper.treeToValue(items, ResponseDto[].class));

// 열거형에 코드와 표시 이름을 함께 둔다.
enum WeatherCode {
    TMP("기온", "℃");

    private final String name;
    private final String unit;
}

오늘의 코드 2 - 예보 응답 가공

ForcastService.java

JsonNode node = objectMapper.readTree(result);
JsonNode item = node.findValue("item");

List<ForcastResponseDTO> list = null;
if(item.isArray()) {
    list = Arrays.asList(
        objectMapper.treeToValue(item, ForcastResponseDTO[].class)
    );
}

list = list.stream()
    .map(dto -> {
        dto.setCategoryName(
            CategoryCode.valueOf(dto.getCategory()).getName()
        );
        String value = CategoryCode.getCodeValue(
            dto.getCategory(),
            dto.getFcstValue()
        );
        String unit = CategoryCode
            .valueOf(dto.getCategory())
            .getUnit();
        dto.setFcstValue(value + unit);
        return dto;
    })
    .toList();

return list;

CategoryCode.java

public enum CategoryCode {
    POP("강수확률", "%"),
    PTY("강수형태", ""),
    SKY("하늘상태", ""),
    TMP("1시간 기온", "℃"),
    WSD("풍속", "m/s");

    private final String name;
    private final String unit;

    public static String getCodeValue(String name, String value) {
        CategoryCode c = CategoryCode.valueOf(name);

        if(c == CategoryCode.SKY) {
            switch(value) {
                case "1" : return "맑음";
                case "3" : return "구름많음";
                case "4" : return "흐림";
            }
        }
        return value;
    }
}

응답 JSON의 item 배열을 DTO 목록으로 변환한 뒤 각 카테고리 코드에 한글 이름과 단위를 추가했다. CategoryCode 열거형은 하늘 상태와 강수 형태처럼 숫자로 전달되는 값을 사용자가 이해할 수 있는 문장으로 변환한다.

const submitHandler = async (event) => {

HTML 날짜와 시간 입력값에서 구분 문자를 제거해 서버 DTO가 요구하는 형식으로 변환했다. POST 요청이 성공하면 응답 데이터와 조회 조건을 라우터 상태에 담아 /openapi/result로 이동하고, 실패하면 오류 메시지를 화면에 표시한다.

어려웠던 점 / 각종 오류

외부 API가 처음에는 400 Bad Request를 반환했다. 요청 URL에서 base_time에 request.getBase_date()를 넣어 날짜가 중복 전송되었고, 엔드포인트에도 실제 기능 경로인 /getVilageFcstBeach가 빠져 있었기 때문에 시간 getter와 전체 요청 주소를 올바르게 수정했다.

주소를 수정한 뒤에는 403 Forbidden이 발생했다. 공공데이터포털의 일반 인증키는 이미 URL 인코딩된 값이므로 toUriString() 과정에서 다시 인코딩되지 않게 build(true)로 URI를 생성해 인증키를 그대로 전달했다.
