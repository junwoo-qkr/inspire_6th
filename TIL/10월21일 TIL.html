오늘 배운 것

Ubuntu 환경 준비와 패키지 설치

가상 환경에 Ubuntu를 준비한 뒤, 관리자 권한으로 필요한 패키지를 설치하는 흐름을 배웠다. 패키지는 프로그램을 설치·관리할 수 있도록 묶은 단위이며, 설치에 앞서 저장소의 패키지 정보를 갱신한다.

명령어 역할
sudo -i 관리자인 root 사용자의 로그인 셸을 시작한다.
apt-get update 설정된 저장소에서 설치 가능한 패키지 목록과 버전 정보를 갱신한다.
apt-get install -y openssh-server curl vim tree 나열한 패키지를 설치하며, -y는 설치 확인 질문에 자동으로 동의하는 옵션이다.

openssh-server는 SSH 원격 접속을 받는 서버이고, curl은 URL을 이용해 데이터를 주고받는 도구다. vim은 터미널 편집기이며, tree는 디렉터리 구조를 트리 형태로 보여준다.

Linux에서 위치 확인과 파일 관리하기

터미널에서는 현재 위치를 확인한 뒤 명령어로 디렉터리를 이동하거나 파일을 관리한다. 명령어 뒤의 경로는 작업 대상을 지정하며, 옵션은 출력 형식이나 동작을 바꾼다.

명령어 역할
pwd 현재 작업 디렉터리의 경로를 출력한다.
ls / ls -al 파일과 디렉터리 목록을 확인한다. -a는 숨김 항목을 포함하고, -l은 권한·소유자·크기 등의 상세 정보를 표시한다.
cd <디렉토리> 지정한 디렉터리로 이동한다.
cd .. / cd ~ / cd - 각각 상위 디렉터리, 현재 사용자의 홈 디렉터리, 직전에 작업한 디렉터리로 이동한다.
mkdir <새 디렉토리> 새 디렉터리를 만든다.
touch <새 파일 이름> 파일이 없으면 빈 파일을 만들고, 이미 있으면 파일의 접근·수정 시간을 갱신한다.
rm <파일 이름> 지정한 파일을 삭제한다.
cp <파일 이름> <새 파일 이름> 원본 파일을 새 이름의 파일로 복사한다.
mv <파일 이름> <디렉토리> 파일을 지정한 디렉터리로 이동한다. 같은 명령으로 파일 이름을 바꿀 수도 있다.

vi의 모드 전환과 편집 명령

vi <파일 이름>으로 편집기를 연다. 일반 모드에서는 키를 편집 명령으로 사용하고, 입력 모드에서는 글자를 입력한다. 저장이나 종료처럼 :으로 시작하는 명령은 일반 모드에서 명령줄을 열어 입력한다.

명령어 또는 키 동작
i / a / o 각각 커서 앞, 커서 뒤, 현재 줄 아래의 새 줄에서 입력 모드로 들어간다.
Esc 입력 모드를 끝내고 일반 모드로 돌아간다.
:w / :q 각각 파일을 저장하거나 편집기를 종료한다. :q는 저장하지 않은 변경 사항이 있으면 종료하지 않는다.
:wq / :x 저장 후 종료한다. :x는 내용이 변경된 경우에만 파일에 쓴다.
:q! 마지막 저장 이후의 변경 사항을 버리고 종료한다.
:set nu / :set nonu 줄 번호 표시를 켜거나 끈다.
dd / yy 현재 줄을 삭제하거나 복사한다. 앞에 숫자를 붙이면 현재 줄부터 해당 줄 수만큼 적용한다.
p / u 복사·삭제한 내용을 붙여 넣거나 직전 편집 작업을 취소한다. 줄 단위로 복사한 내용은 현재 줄 아래에 붙는다.
:%d 파일의 모든 줄을 삭제한다. %는 전체 줄 범위를 뜻한다.
/<검색키워드> 커서 위치에서 문서의 끝 방향으로 키워드를 검색한다.

가상 머신과 컨테이너, 이미지의 관계

가상 머신은 Hypervisor가 제공하는 가상 하드웨어 위에서 게스트 운영체제를 실행한다. Linux 컨테이너는 Docker Engine을 통해 격리된 프로세스를 실행하며, 같은 Docker Host의 커널을 공유한다.

비교 항목 가상 머신 컨테이너
실행 구조 Hypervisor 위에 게스트 운영체제와 애플리케이션을 실행한다. 컨테이너 실행 환경 위에서 애플리케이션을 격리해 실행한다.
운영체제 커널 게스트 운영체제마다 별도의 커널을 사용한다. 같은 호스트의 커널을 공유한다.
용량과 자원 게스트 운영체제 전체를 포함하므로 일반적으로 용량과 실행 자원이 더 많이 필요하다. 애플리케이션과 필요한 파일을 중심으로 구성해 상대적으로 가볍게 실행할 수 있다.

이미지는 실행에 필요한 파일과 환경을 묶은 기반이며, 여러 파일 시스템 레이어로 구성된다. 컨테이너는 이 이미지를 바탕으로 생성한 인스턴스이므로 하나의 이미지에서 여러 컨테이너를 만들 수 있다. 가상 머신 안에 Docker Engine을 설치하면 그 가상 머신이 Docker Host가 된다.

Docker 설치 흐름과 로그인

Ubuntu에서 Docker를 설치하는 흐름은 필요한 패키지 준비, Docker 저장소의 서명 키와 저장소 등록, 패키지 목록 갱신, Docker 패키지 설치로 이어진다. 저장소의 서명 키는 내려받는 패키지의 출처와 무결성을 확인하는 데 사용한다.

  • Docker Engine의 공식 패키지명은 docker-ce다.
  • systemctl status docker로 Docker 서비스 상태를 조회한다.
  • docker version으로 Docker 클라이언트와 서버의 버전 정보를 조회한다.
  • docker login은 이미지 저장소에 인증하는 명령이다. -u로 사용자 이름을 지정하고, 메모의 로그인 방식에서는 비밀번호 입력란에 토큰을 입력한다.

Docker 이미지와 컨테이너 관리 명령

Docker에서는 이미지 목록과 컨테이너 목록을 구분해 조회한다. 이미지로 새 컨테이너를 실행하고, 이름이나 ID로 대상을 지정해 상세 정보를 확인하거나 삭제한다.

명령어 역할과 옵션
docker ps 실행 중인 컨테이너를 조회한다. -a는 중지된 컨테이너까지 포함하고, -q는 ID만 출력한다.
docker images 로컬 이미지 목록을 조회한다. -q를 붙이면 이미지 ID만 출력한다.
docker run 이미지로 새 컨테이너를 생성하고 실행한다. 기본 설정에서는 이미지가 로컬에 없을 때 먼저 다운로드한다.
docker inspect <컨테이너이름 or 이미지이름> 지정한 컨테이너나 이미지의 상세 정보를 조회한다.
docker search <이미지이름> Docker Hub에서 이름에 맞는 이미지를 검색한다.
docker rm <컨테이너이름 or 컨테이너ID> 지정한 컨테이너를 삭제한다. 기본 명령은 중지된 컨테이너에 적용한다.
docker rmi <이미지이름 or 이미지ID> 지정한 로컬 이미지를 삭제한다.

Ubuntu 셸의 $(docker ps -a -q)는 전체 컨테이너의 ID를 출력한 결과를 바깥 명령의 인수로 전달하는 명령 치환이다. 이를 삭제 명령의 대상 목록으로 사용할 수 있으며, 실행 중인 컨테이너는 기본 docker rm으로 삭제되지 않는다.

Nginx 컨테이너 실행과 포트 매핑

Nginx는 웹 요청을 처리하는 웹 서버다. 메모의 docker run -d --name webserver -p 80:80 nginx는 Nginx 이미지로 컨테이너를 실행하면서 실행 방식, 이름, 외부 접속 포트를 함께 지정한다.

구성 요소 의미
docker run 새 컨테이너를 생성하고 실행한다.
-d 컨테이너를 백그라운드에서 실행한다.
--name webserver 컨테이너 이름을 webserver로 지정한다.
-p 80:80 호스트의 80번 포트를 컨테이너의 80번 포트에 연결한다. 앞쪽이 호스트, 뒤쪽이 컨테이너 포트다.
nginx 컨테이너 생성에 사용할 이미지 이름이다.

이 설정에서는 Docker Host의 80번 포트로 들어온 요청이 컨테이너의 80번 포트로 전달된다. 실행 상태는 docker ps에서 조회하고, 웹 서버 응답은 Docker Host의 주소로 접속해 확인한다.
