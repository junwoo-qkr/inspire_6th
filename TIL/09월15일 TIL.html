OpenAI 메시지 역할과 요청 포맷

Chat Completions 요청은 사용할 model과 대화를 담은 messages로 구성한다. 각 메시지는 role과 content를 가지며, 실습에서 다룬 역할은 다음과 같다.

역할의미
system모델이 따를 지침, 역할과 출력 제약을 전달한다.
user사용자의 질문, 요청과 입력 조건을 전달한다.
assistant모델의 답변을 나타낸다. 이전 답변을 대화 이력에 포함하면 이후 요청의 맥락이 된다.

아래는 OpenAIService.recommend()의 요청 구조를 바탕으로 사용자 프롬프트를 줄인 예시다. 메시지 순서는 실제 코드의 List.of(user, system)을 따랐다. ${OPENAI_MODEL}은 설정의 환경 변수 표기이며, 실제 요청에는 설정에서 읽은 모델명이 들어간다.

// JSONC: 구조 설명을 위한 주석이며, 실제 전송하는 JSON에는 주석을 넣지 않는다.
{
  "model": "${OPENAI_MODEL}",
  "messages": [
    {
      "role": "user",
      "content": "주어진 날씨와 지역에 맞는 맛집을 지정한 JSON 형식으로 추천해줘."
    },
    {
      "role": "system",
      "content": "전처리된 JSON 형태로만 반환할 것."
    }
  ]
}

실습 요청에는 이전 대화를 나타내는 assistant 메시지를 넣지 않았다. 직접 호출하는 주소는 https://api.openai.com/v1/chat/completions이며, 모델명은 요청 본문으로 전달한다.

HTTP 요청과 JSON 응답을 Java 객체로 연결하기

Request에 URL, 인증 헤더와 JSON 본문을 담고 OkHttpClient로 실행한다. 응답 전체를 담은 JSON과 그 안에서 모델이 작성한 content 문자열을 구분해야 한다.

메서드변환 방향과 역할
writeValueAsString()Java 객체를 전송 가능한 JSON 문자열로 직렬화한다.
readTree()JSON 문자열을 JsonNode 트리로 읽어 필요한 값을 찾는다.
readValue()JSON 문자열을 지정한 Java 타입으로 역직렬화한다.
 
// Java: 동일한 데이터를 전송용 문자열과 탐색용 트리로 바꿔 본다.
String json = objectMapper.writeValueAsString(Map.of("weather", "비"));
// json의 내용: {"weather":"비"}
JsonNode data = objectMapper.readTree(json);
System.out.println(data.at("/weather").asText()); // 비

실습에서는 응답 전체를 트리로 읽고 /choices/0/message/content에서 생성된 문자열을 꺼냈다. 그 문자열 자체가 DTO 구조에 맞는 JSON일 때 다시 readValue()로 변환한다. 프롬프트로 JSON을 요청하는 것과 실제 응답이 올바른 JSON·타입인지 확인하는 것은 별개의 단계다.

중첩 JSON을 DTO와 정적 중첩 클래스로 표현하기

JSON 배열은 List로, 배열 안의 객체는 별도 DTO 타입으로 표현한다. 관련 DTO를 바깥 응답 DTO 안에 모아 선언하면 데이터의 포함 관계를 함께 읽을 수 있다.

종류특징
내부 클래스static 없이 선언하며, 인스턴스 생성에 바깥 클래스의 객체가 필요하다.
정적 중첩 클래스static class로 선언하며, 바깥 클래스의 객체 없이 생성할 수 있다. 실습의 RestaurantDTO와 Quiz가 해당한다.
 
// Java: 바깥 RecommendResponseDTO 객체를 만들지 않고도 생성할 수 있다.
RecommendResponseDTO.RestaurantDTO item =
    new RecommendResponseDTO.RestaurantDTO();

@JsonIgnoreProperties(ignoreUnknown = true)는 JSON에 존재하지만 DTO에서 인식하지 못하는 속성을 무시한다. 잘못된 JSON 문법이나 필드 타입 불일치를 모두 해결해 주는 설정은 아니다.

Bean 등록과 의존성 주입

Spring이 관리하는 객체를 Bean이라고 한다. @Configuration 안의 @Bean 메서드로 객체를 등록하고, 필요한 서비스가 생성자를 통해 전달받도록 구성할 수 있다.

// Java: 등록된 Bean을 생성자 매개변수로 전달받는 기본 형태다.
public OpenAIService(ChatClient chatClient,
                     ObjectMapper objectMapper,
                     OkHttpClient okHttpClient) {
    this.chatClient = chatClient;
    this.objectMapper = objectMapper;
    this.okHttpClient = okHttpClient;
} // 실습에서는 final 필드와 @RequiredArgsConstructor로 이 생성자를 생성한다.

실습의 OpenAIConfig는 세 객체를 명시적으로 등록한다. ChatClient는 자동 구성된 ChatClient.Builder로 생성하며, ObjectMapper는 Spring Boot의 Jackson 자동 구성으로 제공받을 수도 있다. Bean을 등록해 객체를 전달받는 과정과 ObjectMapper로 데이터를 변환하는 과정은 역할이 다르다.

ChatClient의 문자열 응답과 DTO 응답

ChatClient는 설정된 모델을 바탕으로 프롬프트와 호출 과정을 연결한다. 요청마다 HTTP 주소·인증 헤더·응답 탐색 코드를 직접 조립하는 부분을 줄일 수 있다.

응답 처리사용 목적
.call().content()생성된 글을 String으로 받는다. 블로그 본문 생성에 사용했다.
.call().entity(DTO.class)생성 결과를 지정한 DTO로 변환한다. 맛집 추천과 문제 출제에 사용했다.
 
// Java: 지침과 사용자 요청을 분리하고 생성된 설명을 문자열로 받는다.
String answer = chatClient.prompt()
    .system("처음 배우는 사람에게 쉽게 설명해줘.")
    .user("JSON이 무엇인지 한 문장으로 설명해줘.")
    .call()
    .content(); // answer에는 모델이 생성한 설명이 들어간다.

프로젝트에서는 spring.ai.openai.api-key와 spring.ai.openai.chat.options.model 설정을 사용한다. .entity()의 변환 대상은 일반 Java DTO이며, 데이터베이스의 JPA 엔티티로 저장한다는 뜻은 아니다.

생성된 응답을 React 상태로 관리하기

React에서 서버 응답을 화면에 반영하려면 해당 데이터를 상태에 저장한다. 입력 요소의 value에 상태를 연결하면 상태 변경에 따라 표시되는 값도 갱신된다.

// JavaScript: 응답 데이터를 상태에 넣으면 그 상태를 사용하는 화면이 갱신된다.
const [content, setContent] = useState("");
const applyContent = (text) => setContent(text);
// applyContent("생성된 본문") 호출 후 content는 "생성된 본문"이 된다.

요청에 필요한 인증 정보와 성공 응답의 상태 코드·본문 형식을 백엔드와 맞춰야 한다. 응답으로 작성 칸을 채우는 동작과 그 내용을 게시물로 저장하는 동작은 별개의 요청으로 구성할 수 있다.

MCP와 도구를 사용하는 에이전트

MCP는 AI 애플리케이션이 외부 도구와 데이터를 공통된 방식으로 연결하도록 정한 프로토콜이다. 애플리케이션의 MCP 클라이언트가 MCP 서버와 통신하며, 서버는 도구와 데이터를 제공한다. 서버의 도구가 외부 API를 호출하도록 구현할 수도 있다.

구분연결 대상
로컬 MCP같은 컴퓨터에서 실행되는 MCP 서버와 연결한다.
원격 MCP네트워크를 통해 원격 MCP 서버와 연결한다.

수업에서는 컨트롤러가 받은 요청을 에이전트에 전달하고, 필요한 날씨 조회·가게 검색 도구의 결과를 조합하는 흐름을 다뤘다. 현재 미커밋 블로그 구현은 프롬프트를 보내 본문 문자열을 받는 단계이며, 해당 메서드에 외부 도구를 선택·호출하는 코드는 없다.

오늘의 코드 1 - OpenAI 요청 메시지 구성과 HTTP 호출

OpenAIService.java

// Java: recommend()에서 model과 prompt를 사용해 요청 본문을 구성하는 부분이다.
Map<String, Object> messages = new HashMap<>();
messages.put("model", model);

Map<String, Object> user = new HashMap<>();
user.put("role", "user");
user.put("content", prompt);

Map<String, Object> system = new HashMap<>();
system.put("role", "system");
system.put("content", "전처리된 JSON 형태로만 반환할 것.");

messages.put("messages", List.of(user, system));

String requestJSON = null;
try {
    requestJSON = objectMapper.writeValueAsString(messages);
} catch (JsonProcessingException e) {
    e.printStackTrace();
}

Request request = new Request.Builder()
    .url(endPoint)
    .header("Authorization", "Bearer " + key)
    .header("Content-Type", "application/json")
    .post(RequestBody.create(requestJSON, MediaType.parse("application/json")))
    .build();

 

날씨·지역·추천 결과 형식을 담은 prompt를 사용자 메시지로 넣고, JSON 출력 지침을 별도 메시지로 구성했다. 코드상 Map은 모델명과 메시지 배열을 담는 JSON으로 직렬화되며, API 키는 인증 헤더에 들어간다.

OpenAIService.java

// Java: recommend()의 try 블록 안에서 요청을 실행하고 응답 본문을 읽는다.
response = okHttpClient.newCall(request).execute();
System.out.println("response :\n" + response);

String responseJSON = response.body().string();

 

Request를 만드는 단계와 실제 네트워크 요청을 실행하는 단계를 구분했다. 이 코드에서 얻는 responseJSON은 모델의 답변만이 아니라 API 응답 전체를 담은 문자열이다.

오늘의 코드 2 - 생성된 JSON 문자열을 DTO로 변환

OpenAIService.java

// Java: 응답 전체에서 생성된 텍스트를 찾은 뒤 DTO로 변환한다.
JsonNode node = objectMapper.readTree(responseJSON);
String exr = node.at("/choices/0/message/content").asText();
System.out.println("exr :\n" + exr);

RecommendResponseDTO result = objectMapper.readValue(exr, RecommendResponseDTO.class);
return result;

 

응답 트리의 첫 번째 선택지에서 메시지 내용을 꺼내는 경로를 확인했다. exr이 요청한 구조의 JSON이면 weather, location, restaurants를 가진 RecommendResponseDTO로 변환하도록 작성했다.

오늘의 코드 3 - 배열과 정적 중첩 DTO 구성

RecommendResponseDTO.java

// Java: 추천 응답의 필드와 그 안에 포함되는 음식점 타입을 발췌했다.
private String weather;
private String location;
private List<RestaurantDTO> restaurants;

@Builder
@Getter
@ToString
@NoArgsConstructor
@AllArgsConstructor
@JsonIgnoreProperties(ignoreUnknown = true)
public static class RestaurantDTO {
    private String name;
    private String category;
    private String reason;
}

 

음식점 배열의 각 항목을 이름·분류·추천 이유를 가진 RestaurantDTO로 정의했다. 바깥 RecommendResponseDTO에도 같은 무시 설정이 선언되어 있으며, 각 DTO가 인식하지 못하는 추가 JSON 속성을 무시하도록 구성한 것을 확인했다.

QuizResponseDTO.java

// Java: 문제 목록과 문제 하나의 데이터 구조를 발췌했다.
private List<Quiz> quizes;

@Builder
@Getter
@ToString
@NoArgsConstructor
@AllArgsConstructor
@JsonIgnoreProperties(ignoreUnknown = true)
public static class Quiz {
    private String question;
    private List<String> options;
    private String answer;
    private String desc;
}

 

문제·보기·정답·해설을 하나의 DTO로 묶고 이를 목록으로 받도록 작성했다. 실습 코드에서는 목록 필드와 프롬프트의 JSON 키가 모두 quizes라는 이름을 사용하고 있다.

오늘의 코드 4 - AI 연동 객체를 Bean으로 등록

OpenAIConfig.java

// Java: @Configuration 클래스 안에서 사용할 객체를 Bean으로 등록한다.
@Bean
public ObjectMapper objectMapper() {
    return new ObjectMapper();
}

@Bean
public ChatClient chatClient(ChatClient.Builder builder) {
    return builder.build();
}

@Bean
public OkHttpClient okHttpClient() {
    return new OkHttpClient();
}

 

JSON 변환 객체, AI 대화 클라이언트와 HTTP 클라이언트를 서비스에 주입할 수 있도록 등록했다. 현재 설정은 ObjectMapper를 직접 만들며, ChatClient는 전달받은 빌더로 생성한다.

오늘의 코드 7 - 키워드로 생성한 블로그 본문을 화면에 반영

BlogService.java

// Java: 입력받은 카테고리와 키워드를 사용해 본문 문자열을 생성한다.
public String contentGenerate(Map<String, Object> map) {
    String result = chatClient
        .prompt()
        .user(
            """
                너는 블로그 작성 전문가야.
                주어지는 카테고리와 키워드를 활용해서 차분한 톤의 블로그를 작성해줘.
                글자수는 500자 이내로 작성해줘.
                <조건>
                    - 카테고리 : "%s"
                    - 키워드 : "%s"
                </조건>
            """.formatted(map.get("category"), map.get("keyword")))
        .call()
        .content();

    return result;
}

 

카테고리·키워드·말투·분량을 프롬프트에 넣고 일반 텍스트를 받도록 작성했다. 500자 제한은 모델에 전달한 요청 조건이며, 현재 메서드에는 반환된 글의 길이를 별도로 검사하는 코드가 없다.

요청 JSON을 Map으로 받아 본문 생성 서비스에 넘긴다. 정상적으로 메서드가 끝나면 DTO 포장이 없는 본문 문자열을 201 Created로 반환하도록 연결되어 있다.

BlogWritePage.jsx

// JSX: keyword 상태를 변경하고, 클릭 시 전송 함수를 호출하는 입력 영역이다.
<TextInput

    value={keyword}
    placeholder="키워드를 입력하세요"

        setKeyword(e.target.value);
    }} />

입력한 값을 keyword 상태에 반영하고, 버튼 클릭을 keywordHandler에 연결했다. 현재 파일에서 버튼 prop 이름이 onClick으로 작성된 것을 확인했다.

BlogWritePage.jsx

// JavaScript: 카테고리와 키워드를 전송하고 응답 본문으로 상태를 갱신한다.
const keywordHandler = async () => {
    console.log(`keyword : ${keyword}`);

    await api.post("/blog/ai/agent", {
        category,
        keyword
    }, {
        headers : {Authorization : at ? at : ""}
    })
        .then(response => {
            if(response.status === 201) {
                setContent(response.data);
            }
        })
        .catch(err => {
            console.log(err);
        })
}

 

카테고리·키워드와 저장된 인증 값을 보내고, 상태 코드가 201이면 응답 문자열을 content에 넣는다. 본문 입력 요소는 value={content}를 사용하므로 상태 변경을 화면에 반영하는 구조다. 이 요청은 작성 칸을 채우며, 게시물 저장은 별도의 /blog/write 요청으로 처리한다.

어려웠던 점 / 각종 오류

키워드 전송 버튼을 눌러도 keywordHandler가 실행되지 않는 원인을 확인했다. 버튼에 전달한 이름은 onclick이었지만, 사용하는 Button 컴포넌트는 props.onClick을 읽고 있었다. JavaScript는 대소문자를 구분하므로 서로 다른 prop이 되어 이벤트 함수가 연결되지 않았고, 전달 이름을 onClick으로 맞추는 것이 해결 방법이었다. 현재 BlogWritePage.jsx에는 이 수정이 반영되어 있다.

수업 메모에 남긴 내부 클래스 질문은 DTO의 선언 형태를 기준으로 구분했다. 클래스 안에 정의했다고 모두 같은 생성 방식을 쓰는 것은 아니며, 실습의 RestaurantDTO와 Quiz는 static이 붙어 있어 바깥 DTO 객체 없이 생성할 수 있는 정적 중첩 클래스다.
