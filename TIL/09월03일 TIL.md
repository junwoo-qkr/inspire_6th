# 제목: Spring Boot·MyBatis 댓글 API와 React 상태 동기화

## 오늘의 한 줄 요약

- 세션과 토큰 기반 인증의 차이를 살펴보고, 로그인 응답 헤더로 Access Token과 Refresh Token을 전달하는 흐름을 확인했다.
- `@PathVariable`, `@RequestHeader`, `@RequestBody`로 URL 경로·요청 헤더·JSON 본문을 각각 Controller 매개변수에 연결했다.
- 게시글과 댓글을 각각 조회한 뒤 하나의 트랜잭션 안에서 `BlogResponseDTO`로 조합했다.
- MyBatis `<selectKey>`로 댓글 ID를 먼저 생성하고 같은 요청 DTO에 저장해 INSERT와 응답에 사용했다.
- 댓글 생성 API가 새 댓글 객체 하나를 반환하게 하고, React 상태 배열의 앞에 추가해 새로고침 없이 최신 댓글을 맨 위에 표시했다.

## 키워드 정리

| 키워드 | 설명 또는 예시 |
| --- | --- |
| 세션 | 서버가 클라이언트의 이전 상태를 식별하기 위해 세션 ID를 사용하는 방식이다. 서비스가 여러 개로 나뉘면 서비스 사이에서 세션 정보를 공유하는 문제가 생길 수 있다. |
| JWT | 토큰 기반 인증에 사용하는 형식으로 Header, Payload, Signature로 구성된다. 현재 실습의 `JwtProvider`는 실제 JWT가 아닌 고정 문자열을 반환한다. |
| Access Token | 인증이 필요한 API를 호출할 때 `Authorization` 요청 헤더에 담는 토큰이다. |
| Refresh Token | Access Token이 만료됐을 때 새 Access Token을 발급받는 데 사용하는 토큰이다. |
| `Access-Control-Expose-Headers` | 브라우저의 JavaScript가 CORS 응답의 사용자 정의 헤더를 읽을 수 있도록 공개한다. 예: `Authorization, Refresh-Token` |
| `@RequestHeader` | 요청 헤더를 Controller 매개변수로 받는다. 예: `@RequestHeader("Authorization") String at` |
| `@PathVariable` | URL 경로에 포함된 값을 받는다. 예: `@GetMapping("/read/{postId}")` |
| `@RequestBody` | JSON 요청 본문을 DTO로 변환한다. Spring의 `org.springframework.web.bind.annotation.RequestBody`를 사용해야 한다. |
| `@Transactional(readOnly = true)` | 게시글과 댓글 조회를 하나의 읽기 전용 트랜잭션 경계 안에서 처리한다. |
| `toBuilder()` | 기존 객체 값을 복사한 Builder를 만들고 필요한 필드만 추가한다. 예: `post.toBuilder().comments(comments).build()` |
| `<selectKey>` | INSERT 전후에 키를 조회해 매개변수 객체에 저장한다. 예: `<selectKey keyProperty="id" order="BEFORE">` |
| MyBatis `#{}` | DTO 값이나 매개변수 값을 SQL에 바인딩한다. SQL 함수인 `NEXTVAL(...)` 자체에는 `#{}`를 사용하지 않는다. |
| 함수형 상태 갱신 | 이전 상태를 기준으로 안전하게 새 상태를 만든다. 예: `setComments(items => [newComment, ...items])` |
| React `key` | 목록 항목의 고유 ID를 사용해 렌더링 전후의 같은 항목을 식별한다. 예: `key={comment.id}` |

## 오늘 배운 것

### 세션과 토큰 기반 인증 흐름

- 세션 방식은 서버가 발급한 세션 ID를 기준으로 이전 상태를 찾는다. 여러 서비스로 나뉜 환경에서는 각 서비스가 같은 세션 정보를 어떻게 공유할지 고려해야 한다. 토큰 방식은 클라이언트가 토큰을 보관하고 요청마다 전달한다. 오늘 실습에서는 로그인 성공 시 서버가 `Authorization`과 `Refresh-Token` 응답 헤더를 만들고, React가 두 값을 `localStorage`에 저장하는 흐름을 확인했다. 브라우저에서 이 헤더를 읽으려면 서버가 `Access-Control-Expose-Headers`로 헤더 이름을 공개해야 한다. 현재 `JwtProvider`가 반환하는 값은 실제 서명된 JWT가 아니라 인증 흐름을 확인하기 위한 고정 문자열이다.

| 구분 | 세션 | 토큰 |
| --- | --- | --- |
| 상태 정보의 중심 | 서버가 세션 정보를 관리 | 클라이언트가 토큰을 보관해 요청마다 전달 |
| 클라이언트가 전달하는 값 | 세션 ID | Access Token |
| 수업에서 확인한 토큰 | 해당 없음 | Access Token, Refresh Token |
| 서비스 분리 시 고려점 | 서비스 간 세션 정보 공유 | 각 서비스가 토큰을 검증하는 방식 |

```java
HttpHeaders headers = new HttpHeaders();
headers.add("Authorization", accessToken);
headers.add("Refresh-Token", refreshToken);
headers.add("Access-Control-Expose-Headers", "Authorization, Refresh-Token");
```

### 요청 데이터 위치에 맞는 Spring MVC 어노테이션

- 요청값이 있는 위치에 따라 사용하는 어노테이션이 다르다. 게시글 번호는 `/blog/read/{postId}` 경로에서 `@PathVariable`로 받고, Access Token은 `Authorization` 헤더에서 `@RequestHeader`로 받는다. 게시글과 댓글 작성 시 Axios가 전송한 JSON은 Spring의 `@RequestBody`로 DTO에 바인딩한다. Swagger의 `io.swagger.v3.oas.annotations.parameters.RequestBody`는 API 문서 작성용이므로 JSON 바인딩을 대신하지 않는다.

| 요청 데이터 위치 | Spring MVC 어노테이션 | 현재 실습 예시 |
| --- | --- | --- |
| URL 경로 | `@PathVariable` | `/blog/read/{postId}` |
| HTTP 헤더 | `@RequestHeader` | `Authorization` |
| JSON 본문 | `@RequestBody` | `BlogRequestDTO`, `CommentRequestDTO` |
| 쿼리 문자열 | `@RequestParam` | 로그인 `email`, `password` |

```java
@GetMapping("/read/{postId}")
public ResponseEntity<?> read(
        @PathVariable Integer postId,
        @RequestHeader("Authorization") String accessToken) {
    // 게시글 조회
}
```

### 게시글과 댓글을 하나의 응답 DTO로 조합하기

- 게시글 한 건과 그 게시글의 댓글 목록은 서로 다른 Mapper로 조회한다. `BlogResponseDTO`에 `List<CommentResponseDTO>`를 선언하고, `BlogService.read()`에서 게시글 조회 결과를 `toBuilder()`로 복사한 다음 댓글 목록을 추가했다. 두 조회는 `@Transactional(readOnly = true)`가 붙은 하나의 서비스 메서드 안에서 실행된다. Controller는 조합된 DTO 하나만 React에 반환한다.

```java
@Transactional(readOnly = true)
public BlogResponseDTO read(Integer postId) {
    BlogResponseDTO post = blogMapper.findById(postId)
        .orElseThrow(() -> new RuntimeException("NOT FOUND. postID : " + postId));

    return post.toBuilder()
        .comments(commentMapper.findByPostId(post.getId()))
        .build();
}
```

| `SPRING_COMMENT_TBL` | `ID`, `COMMENT`, `POSTID`, `EMAIL` | `POSTID`가 게시글을, `EMAIL`이 사용자를 참조한다. |

### MyBatis `selectKey`로 생성 ID 받기

- React가 보내는 댓글 작성 요청에는 아직 댓글 ID가 없다. MyBatis는 `order="BEFORE"`인 `<selectKey>`를 INSERT보다 먼저 실행해 `COMMENTID` 시퀀스 값을 가져온다. `keyProperty="id"`가 조회 결과를 같은 `CommentRequestDTO` 객체의 `id` 필드에 넣는다. 따라서 `commentMapper.write(request)`를 호출하기 전에는 `request.getId()`가 `null`이지만 호출 후에는 생성된 ID를 읽을 수 있다. Mapper의 INSERT 반환값은 생성 ID가 아니라 반영된 행 수라는 점과 구분해야 한다.

| 값 | 의미 |
| --- | --- |
| `commentMapper.write(request)` 반환값 | INSERT로 반영된 행 수 |
| `request.getId()` | `<selectKey>`가 DTO에 저장한 댓글 ID |

```xml
<selectKey keyProperty="id" resultType="int" order="BEFORE">
    SELECT NEXTVAL(COMMENTID)
</selectKey>
```

---

### 생성된 댓글 한 건과 React 상태 동기화

- React의 `setComments(arr => [response.data, ...arr])`는 `response.data`가 댓글 객체 한 개일 때 맞는 코드다. 따라서 댓글 작성 API도 전체 댓글 목록이 아니라 방금 작성된 댓글의 `id`, `comment`, `email`, `postId`를 `CommentResponseDTO` 하나로 반환했다. 새 댓글을 배열 앞에 넣으면 MyBatis 조회문의 `ORDER BY ID DESC`와 같은 최신순을 새로고침 없이 유지할 수 있다. 목록의 `key`도 배열 인덱스가 아니라 `comment.id`를 사용해야 새 항목이 앞에 추가됐을 때 컴포넌트가 잘못 재사용되지 않는다.

```jsx
setComments(previousComments => [response.data, ...previousComments]);
```

```jsx
<BlogCommentItem key={comment.id} comment={comment} />
```

## 오늘의 코드 3 - 게시글·댓글 테이블 관계 구성하기

`rds/script/mybatisquery.sql`

```sql
ALTER TABLE SPRING_USER_TBL
ADD CONSTRAINT PRIMARY KEY(EMAIL);

CREATE SEQUENCE POSTID
START WITH 1
INCREMENT BY 1
NOCYCLE;

CREATE TABLE SPRING_POST_TBL(
    ID INT DEFAULT NEXTVAL(POSTID) PRIMARY KEY,
    TITLE VARCHAR(50) NOT NULL,
    CONTENT VARCHAR(200) NOT NULL,
    CATEGORY VARCHAR(50) CHECK(CATEGORY IN ('개발', '생활', '취미', '일상')),
    EMAIL VARCHAR(50) REFERENCES SPRING_USER_TBL(EMAIL)
);

CREATE SEQUENCE COMMENTID
START WITH 1
INCREMENT BY 1
NOCYCLE;

CREATE TABLE SPRING_COMMENT_TBL(
    COMMENT VARCHAR(200) NOT NULL,
    POSTID INT REFERENCES SPRING_POST_TBL(ID),
    EMAIL VARCHAR(50) REFERENCES SPRING_USER_TBL(EMAIL),
    ID INT DEFAULT NEXTVAL(COMMENTID) PRIMARY KEY
);
```

사용자 이메일을 기준으로 게시글과 댓글의 작성자를 연결하고, 댓글의 `POSTID`로 게시글과 댓글의 일대다 관계를 만들었다.

## 어려웠던 점 / 각종 오류

`localhost:3000/blog/index`는 React Router의 화면 경로이고 Spring Boot API는 8000번 포트를 사용한다. React가 존재하지 않는 `/posts` API를 호출해 404가 발생했으며, 실제 Controller 매핑인 `/blog/index`로 요청 주소를 맞춰 해결했다.

게시글 작성 요청의 모든 필드가 `null`이 된 원인은 `BlogController`가 Swagger 문서용 `RequestBody`를 import한 것이었다. JSON 바인딩에는 다음 Spring MVC 어노테이션을 사용해야 한다.

```java
import org.springframework.web.bind.annotation.RequestBody;
```

댓글 작성 API가 전체 댓글 목록을 반환하는데 React에서 `response.data`를 댓글 한 개처럼 기존 배열에 추가하면 배열 안에 배열이 들어간다. React 코드를 유지하기 위해 서버가 `CommentResponseDTO` 한 건을 반환하도록 응답 구조를 맞췄다.

```text
[기존 댓글, [새 댓글, 기존 댓글]]
```

새 댓글을 배열 뒤에 추가하면 새로고침 전에는 맨 아래에 보이지만, 서버 재조회 결과는 `ORDER BY ID DESC`라서 새로고침 후 맨 위로 이동했다. `setComments(arr => [response.data, ...arr])`로 앞에 추가하고 `key={comment.id}`를 사용해 순서와 컴포넌트 식별을 함께 맞췄다.

`<selectKey order="BEFORE">`는 INSERT 전에 ID를 생성해 `request.id`에 넣는다. 따라서 `request.getId()`는 생성된 ID이고 `commentMapper.write(request)`의 반환값은 반영 행 수다. 두 값을 구분해야 ID 생성 여부와 INSERT 성공 여부를 혼동하지 않는다.

현재 댓글 POST 코드의 `headers`는 요청 본문 객체 안에 들어 있어 실제 HTTP 헤더로 전송되지 않는다. Axios POST에서 헤더를 보내려면 데이터와 설정을 분리해 세 번째 인수로 전달해야 한다.

```jsx
api.post(
    "/comments/write",
    { comment, postId: Number(postId), email: user },
    { headers: { Authorization: at || "" } }
);
```
