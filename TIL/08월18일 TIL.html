오늘의 한 줄 요약

  • 컬렉션으로 여러 객체를 관리하고 제네릭으로 저장·조회할 타입을 지정했다.
  • 람다와 함수형 인터페이스로 동작을 전달하고, 스트림으로 조건 선택과 값 변환을 연결했다.
  • 표현·업무·데이터 접근 계층의 역할과 DTO를 통한 데이터 전달을 정리했다.

키워드 정리

키워드 설명 또는 예시
List / Set / Map 순서 있는 목록 / 중복 없는 집합 / 키와 값의 대응
박싱·언박싱 Integer n = 10; int value = n;
제네릭 ResponseTemplate<T>처럼 사용하는 쪽에서 타입 지정
와일드카드 ? extends T는 읽기 중심, ? super T는 T 추가 중심
함수형 인터페이스 추상 메서드 하나의 동작을 람다로 구현
메서드 참조 System.out::println으로 기존 메서드 전달
스트림 파이프라인 stream → filter/map → collect/forEach
DTO 계층 사이에서 전달할 데이터를 담는 객체

오늘 배운 것

컬렉션과 래퍼 클래스

List와 Set은 Collection의 하위 인터페이스이고, Map은 별도의 인터페이스다. 컬렉션의 제네릭 요소 타입에는 참조 타입을 사용하며, 기본 타입 값은 래퍼 객체로 자동 박싱할 수 있다.

실습 구현체 순서와 중복
ArrayList 추가한 순서를 유지하며 같은 값을 여러 번 저장한다.
HashSet 중복을 제거하며 반복 순서를 보장하지 않는다.
HashMap 반복 순서를 보장하지 않으며 같은 키로 저장하면 기존 값을 바꾼다. 값은 중복 가능하다. 
// Java
List<Integer> numbers = new ArrayList<>();
numbers.add(10);          // int를 Integer로 박싱
int first = numbers.get(0); // Integer를 int로 언박싱
System.out.println(first); // 10

제네릭 응답과 와일드카드

제네릭은 컴파일 시 타입을 검사하고 조회 결과에 불필요한 형변환을 줄인다. T, E, K, V는 이름을 붙이는 관례이며, N이라고 쓰는 것만으로 숫자 타입에 제한되지는 않는다.

타입 가능한 사용
List<T> T 및 하위 타입 객체를 추가하고 T로 읽는다.
List<? extends T> T 또는 하위 타입의 리스트를 받는다. T로 읽을 수 있지만 구체적인 요소 타입을 모르므로 일반적인 객체 추가가 제한된다.
List<? super T> T 또는 상위 타입의 리스트를 받는다. T와 그 하위 타입을 추가하고, 읽은 값은 Object로 받는다. 
// Java
List<Integer> source = new ArrayList<>();
source.add(10);
List<? extends Number> read = source;
Number n = read.get(0); // 상위 타입 Number로 읽기
List<? super Integer> write = new ArrayList<Number>();
write.add(20);          // Integer를 안전하게 추가
Object value = write.get(0); // 읽기는 Object로 받기

람다와 함수형 인터페이스

람다는 함수형 인터페이스의 추상 메서드 구현을 간결하게 전달한다. 선언만으로 실행되지는 않고 해당 인터페이스의 메서드를 호출할 때 동작한다.

인터페이스 입력 → 결과 / 실행 메서드
Supplier<T> 없음 → T / get()
Consumer<T> T → 없음 / accept()
Function<T, R> T → R / apply()
Predicate<T> T → boolean / test() 
// Java
Function<String, Integer> length = text -> text.length();
// text -> { return text.length(); }를 줄인 표현
System.out.println(length.apply("Java")); // 4
Consumer<String> print = System.out::println;
// text -> System.out.println(text)와 같은 역할
print.accept("Java"); // Java

스트림의 중간 연산과 최종 연산

filter는 조건에 맞는 요소를 남기고, map은 각 요소를 다른 값으로 변환한다. 중간 연산은 최종 연산이 실행될 때 처리되며, collect는 결과를 모으고 forEach는 요소별 작업을 수행한다. 최종 연산을 마친 스트림은 다시 사용할 수 없다.

// Java
List<String> words = Arrays.asList("spring", "java");
List<String> result = words.stream()
    .filter(word -> word.startsWith("s")) // 조건 선택
    .map(String::toUpperCase)             // word -> word.toUpperCase()
    .collect(Collectors.toList());        // 결과 목록 생성
System.out.println(result); // [SPRING]

이 예시는 원본 목록을 수정하지 않고 결과를 만든다. 다만 람다에서 원본 객체를 직접 수정하면 변경이 남을 수 있다. stream()은 순차 스트림이며, 반복문이나 병렬 처리보다 항상 빠르다고 단정할 수 없다.

계층의 역할과 DTO 전달

계층 역할
표현 계층 요청을 받고 응답을 전달한다.
비즈니스 계층 업무 규칙과 데이터 가공을 담당한다.
영속성 계층 데이터 저장소에 접근한다.

DTO는 전달할 데이터를 묶는 객체다. 조회한 한 행을 DTO 한 개로, 여러 행을 DTO 목록으로 표현할 수 있지만 테이블 전체와 DTO가 항상 일대일 대응할 필요는 없다. 컬럼과 필드의 이름·타입은 매핑 또는 변환 규칙으로 연결할 수 있다.

오늘의 코드 1 - List와 Set의 데이터 관리

CollectionApp.java

// Java
List<String> list = new ArrayList<>();
list.add("HI");
System.out.println("list.size() = " + list.size());

Set<String> set = new HashSet<>();
set.add("John");
set.add("Bobby");
set.add("Tom");
set.add("John");
set.add("Britney");
set.add("Adam");
System.out.println("set = " + set);

 

리스트에는 문자열 한 개가 저장되어 크기가 1로 출력됐다. 집합에는 John을 두 번 추가했지만 서로 다른 이름 다섯 개만 남았으며 출력 순서는 보장되지 않는다.

오늘의 코드 2 - 제네릭 응답에 DTO와 목록 담기

GenericsApp.java

// Java
ResponseTemplate<PersonDTO> response =
    new ResponseTemplate<PersonDTO>(201, "CREATED", student);
System.out.println(response.getData().personInfo());

ResponseTemplate<List<PersonDTO>> response2 =
    new ResponseTemplate<List<PersonDTO>>(200, "OK", personList);
List<PersonDTO> lst = response2.getData();

 

Cindy 학생 DTO와 Cindy·Greg·Paul이 담긴 목록을 같은 응답 클래스에 각각 넣었다. ResponseTemplate의 T data 덕분에 DTO와 목록을 지정한 타입으로 꺼낼 수 있었다.

오늘의 코드 3 - 와일드카드로 여러 DTO 목록 묶기

CollectionApp.java

// Java
Map<String, List<? extends PersonDTO>> map = new HashMap<>();
map.put("student", studentList);
map.put("teacher", teacherList);
map.put("manager", managerList);
List<? extends PersonDTO> mapList = map.get("manager");
mapList.forEach(person -> System.out.println(person.personInfo()));

 

학생·교사·관리자 목록을 문자열 키로 구분하고 공통 부모 타입으로 읽었다. 이 구간의 세 목록은 비어 있으므로 반복 출력은 발생하지 않았다.

오늘의 코드 4 - 람다 구현과 Consumer 작업 연결

InspireFunction.java

// Java
@FunctionalInterface
public interface InspireFunction {
    public int max(int x, int y);
}

 

두 정수를 받아 정수를 반환하는 추상 메서드 하나를 선언했다. 이름이 max여도 실제 계산은 전달한 람다 구현으로 결정된다.

StreamApp.java

// Java
InspireFunction func01 = (x, y) -> x > y ? x : y;
InspireFunction func02 = (x, y) -> x + y;
System.out.println("func01 = " + func01.max(100, 200));
System.out.println("func02 = " + func02.max(100, 200));

Consumer<String> consumer = (str) -> System.out.println(str.split(" ")[0]);
consumer.andThen(System.out::println).accept("Hi There");

 

최댓값 람다는 200, 덧셈 람다는 300을 반환했다. andThen은 같은 입력으로 작업을 이어 실행하여 Hi 다음 줄에 Hi There를 출력했다.

오늘의 코드 5 - DTO 목록을 스트림으로 필터링하고 변환하기

CollectionApp.java

// Java
List<String> filterdList2 = personList.stream()
    .filter(s -> s.getName().startsWith("s"))
    .map(s -> s.getName().toUpperCase())
    .collect(Collectors.toList());
System.out.println(filterdList2);

 

student·teacher·manager 중 이름이 s로 시작하는 객체를 선택했다. 선택한 이름을 대문자로 바꿔 모은 결과는 [STUDENT]였다.

어려웠던 점 / 각종 오류

? extends PersonDTO와 ? super PersonDTO는 실제 요소 타입을 어느 범위까지 확신할 수 있는지 구분해야 했다. 전자는 부모 타입으로 읽는 데 적합하고, 후자는 부모 및 하위 타입 객체를 넣는 데 적합하며 읽기는 Object로 받는다.

스트림은 원본 컬렉션과 수명이 다르다. 같은 데이터를 다시 처리하려면 기존 스트림을 재사용하지 않고 stream()으로 새 스트림을 만든다.
