## 오늘 배운 것

### Java 실행 환경과 컴파일 과정

- 수업에서는 JDK 17과 VS Code의 Extension Pack for Java를 사용했다. `.java` 소스는 컴파일러를 거쳐 `.class` 바이트코드가 되고, 해당 버전과 라이브러리를 지원하는 JVM에서 실행된다.

| 구성 요소 | 역할 |
| --- | --- |
| JVM | 바이트코드를 실행하는 가상 머신 |
| JRE | JVM과 실행에 필요한 라이브러리 등으로 구성되는 실행 환경 |
| JDK | 컴파일러 등 개발 도구와 실행에 필요한 구성 요소 제공 |

- `JAVA_HOME`은 JDK 설치 위치를 가리킨다. Windows의 `Path`에 JDK의 `bin` 경로를 등록하면 다른 폴더에서도 `java`, `javac`를 호출할 수 있다. 개발 도구와 실제 터미널에서 사용하는 JDK 버전을 맞추는 것이 중요하다.
- `main`은 이번 수업에서 사용하는 프로그램의 실행 시작점이다. 다른 클래스는 실행 클래스에서 객체를 만들어 사용하며, `main`이 없는 클래스도 컴파일할 수 있다.

```java
public static void main(String[] args) {
    System.out.println("Hello Java");
}
```

### 변수의 타입과 선언 위치

- 변수는 타입을 지정해 선언한다. 기본 타입 변수에는 해당 타입의 값을 저장하고, 참조 타입 변수에는 객체를 가리키는 참조값이나 `null`을 저장한다.

| 분류 | 타입 |
| --- | --- |
| 정수 | `byte`, `short`, `int`, `long` |
| 실수 | `float`, `double` |
| 문자 | `char` |
| 논리 | `boolean` |
| 참조 | `String`, 배열, 사용자가 정의한 클래스 등 |

| 구분 | 선언 위치 | 초기화와 접근 |
| --- | --- | --- |
| 멤버 변수(필드) | 클래스 내부 | 기본값이 부여되며 접근 지정자를 사용할 수 있음 |
| 지역 변수 | 메서드 등 블록 내부 | 읽기 전에 값을 대입하고 해당 범위에서 사용 |

- 필드의 기본값은 정수 `0`, 실수 `0.0`, 문자 `'\u0000'`, 논리 `false`, 참조 `null` 등이다. `boolean`은 참·거짓을 표현하며 구체적인 저장 방식은 JVM 구현에 따른다.

```java
class Example {
    private int count; // 필드: 기본값 0
    public void print() {
        int step = 3; // 지역 변수: 사용 전 초기화
        System.out.println(count + step); // 3
    }
}
```

### 클래스와 인스턴스, 객체 사이의 관계

- 클래스는 필드와 메서드로 상태와 동작을 정의하고 생성자로 초기화 방법을 제공한다. `new`로 생성한 객체가 인스턴스이며, 참조 변수로 그 객체의 허용된 멤버에 접근한다.
- 인스턴스 필드는 객체마다 따로 존재한다. 객체가 다른 객체를 필드로 보유하는 구성 관계를 Has-a로 설명할 수 있다. 관련된 상태와 동작을 한 클래스에 모으고 불필요한 의존을 줄이는 것이 응집도와 결합도를 고려한 설계이다.

```java
Car first = new Car("BMW");
Car same = first; // 같은 객체를 가리키는 참조값을 복사
System.out.println(first == same); // true
```

### 생성자 오버로딩과 this

- 생성자는 클래스와 이름이 같고 반환 타입을 적지 않는다. 매개변수의 개수·타입·순서를 달리해 여러 초기화 방법을 제공하는 것이 생성자 오버로딩이다. `this`는 현재 인스턴스를 가리키므로 필드와 매개변수의 이름이 같을 때 구별할 수 있다.
- 생성자를 하나도 선언하지 않은 클래스에는 컴파일러가 기본 생성자를 제공한다. 직접 생성자를 선언했다면, 무인자로 생성할 필요가 있을 때 무인자 생성자도 명시한다.

```java
class Car {
    private String brand;
    public Car() {}
    public Car(String brand) {
        this.brand = brand;
    }
}
```

---

### 접근 제어와 캡슐화

- 필드를 `private`으로 두고 생성자나 getter·setter로 조회·수정 경로를 제공한다. getter는 값을 반환하고 setter는 값을 변경한다. 유효한 값만 허용하려면 해당 경로에 검증 로직을 직접 작성한다.
- 블로그의 `Teacher` 예제는 `public` 필드 직접 접근과 메서드 접근을 비교하고, `Car` 예제는 `private` 필드로 직접 접근을 제한한다.

```java
private String brand;
public String getBrand() { return brand; }
public void setBrand(String brand) { this.brand = brand; }
```

### DTO와 Lombok을 이용한 객체 생성

- DTO는 제목·내용·이메일 등 함께 이동하는 데이터를 묶는 객체이다. 요청 DTO와 응답 DTO는 각각 전달 방향에 맞는 데이터를 담는다. JSON과 DTO의 변환은 이를 처리하는 라이브러리나 프레임워크와 연결되는 별도 과정이다.

| 용어 | 주요 역할 |
| --- | --- |
| DTO | 계층이나 시스템 사이에서 데이터 전달 |
| VO | 값 자체의 의미를 표현하는 객체 |
| Entity | 식별성을 가진 도메인 객체로, 영속성 기술에서 테이블과 매핑될 수 있음 |

| Lombok 어노테이션 | 생성하는 기능 |
| --- | --- |
| `@Getter` | 필드 조회 메서드 |
| `@Setter` | 필드 변경 메서드 |
| `@NoArgsConstructor` | 무인자 생성자 |
| `@AllArgsConstructor` | 대상 필드를 선언 순서대로 받는 생성자 |
| `@Builder` | Builder를 이용한 객체 생성 기능 |

- Builder는 필드 이름을 드러내며 값을 지정하고 마지막 `build()`로 객체를 만든다. 블로그의 DTO 필드는 `id`, `title`, `content`, `email` 순서이므로 전체 인자 생성자도 이 순서에 맞춰 사용한다. setter가 있는 DTO는 생성 후에도 수정할 수 있다.

```java
BlogRequestDTO byConstructor = new BlogRequestDTO(3, "ABC", "Hi", "mail");
BlogRequestDTO byBuilder = BlogRequestDTO.builder()
    .id(3).title("ABC").content("Hi").email("mail").build();
```

- 강의 정리에서는 Maven·Gradle과 YAML도 소개했다. Maven·Gradle은 빌드와 의존성 관리를 담당하고, YAML은 설정 데이터를 표현하는 형식이다.

### 형변환과 래퍼 클래스

- 기본 타입 간 변환에서는 표현 범위와 정밀도를 고려한다. 명시적 캐스팅으로 실수를 정수로 바꾸면 소수 부분이 제거된다. `char`는 UTF-16 코드 단위를 표현하며 `int`로 변환해 수치값을 확인할 수 있다.
- 래퍼 클래스는 기본 타입을 객체로 다룬다. 기본값을 래퍼로 변환하는 과정이 박싱이고, 래퍼에서 기본값을 꺼내는 과정이 언박싱이다. 래퍼는 `null`을 표현할 수 있으므로 언박싱 전 값의 존재 여부를 고려한다.

```java
int number = (int) 3.8; // 3
int code = 'A';        // 65
Integer boxed = number; // 박싱
int unboxed = boxed;     // 언박싱
```

## 오늘의 코드 4 - Lombok DTO와 Builder

BlogRequestDTO.java

```java
@Builder
@NoArgsConstructor
@AllArgsConstructor
@Setter
@Getter
public class BlogRequestDTO {
    private Integer id;
    private String title;
    private String content;
    private String email;
}
```

BlogApp.java

```java
BlogRequestDTO request3 = BlogRequestDTO.builder()
    .title("ABC").content("Hi").id(3).build();
request3.setEmail("AAA@gmail.com");
System.out.println(request3.getContent());
```

반복 코드를 어노테이션으로 생성하고 Builder로 필요한 필드를 지정했다.
