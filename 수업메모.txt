외래키: 참조무결성(부모에 의존하는 데이터 또는 NULL)
옵션: ON DELETE [CASCADE | NO ACTION], ON UPDATE [CASCADE | NO ACTION]
CASCADE: 부모가 업데이트 OR 삭제되면 함께 업데이트 OR 삭제
NO ACTION: NULL값으로 대체

DEFAULT의 값으로는 고정값을 주는게 좋음

NOT NULL은 테이블 레벨로 제약을 못 검

ALTER: 테이블 스키마 수정, 제약조건 추가 변경
ADD, DROP CONSTRAINT
ADD COLUMN
CHANGE COLUMN OLD NEW TYPE <- 이름과 타입 변경
MODIFY COLUMN OLD TYPE <- 타입 변경
DROP COLUMN COLUMN_NAME
데이터가 들어있을 때는 타입 변경 안됨

RENAME: 테이블 이름 변경

기본키가 두개: 테이블 수준에서 제약조건 걸기

여러개의 기본키를 다른 테이블에서 참조: 여러 기본키를 하나로 묶어서 제약조건 걸기

VIEW: 가상의 논리적 테이블(읽기 전용)
보안 및 질의어의 단순화를 위해 사용
사용자는 테이블에 바로 접근하는게 아니라 뷰를 통해 접근
복합 뷰에 대해서는 입력 수정 삭제가 안됨

from절의 서브쿼리가 inline view인 이유: 임시로 만들어진 view였기 때문

DML
UPDATE, INSERT, DELETE <- transaction을 발생시킴
ROLLBACK: transaction을 원상복귀시킴
DML은 기본값이 auto commit

update: 테이블의 기존 데이터를 수정(행 수는 그대로)
update table_name
set column_name = { value | subquery | default }
where condition = { value | subquery }

insert: 테이블에 데이터 추가
insert into table_name([column_name]) values(values);
column_name과 values는 타입, 순서, 개수를 맞춰야함

delete: 테이블의 데이터 삭제(행의 수가 달라짐)
delete from table_name where condition;
참조 관계를 가지는 데이터는 삭제할 때 조심하기

sequence: auto-increment하는 숫자를 생성하는 객체
create sequence sequence_name
START WITH 시작번호
increment by step
maxvalue 끝 번호
[ cycle | nocycle ] ;

nextval()
lastval()

auto-increment 옵션은 sequence랑 비슷하지만 테이블에 종속적
