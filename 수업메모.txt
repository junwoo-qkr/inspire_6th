컨트롤러, 서비스, 레포지토리가 팩토리에 등록(singleton으로)

프레임워크가 관리하는 객체: bean

객체생성을 위임하는 방법
- .xml (스키마 기반): 태그 사용
- annotation 기반

@Component를 상속받는 annotation들
- @Controller - 클래스 첫 글자를 소문자로 하는 객체를 자동으로 생성, 액션을 수행하고 페이지 반환
- @RestController - 클래스 첫 글자를 소문자로 하는 객체를 자동으로 생성, 액션을 수행하고 데이터(json) 반환
- @Service
- @Repository
- @Mapper

@RequestMapping(/demo) 클래스는 http:// ip : port / demo 까지의 url에 매핑됨
@GetMapping(/index) 메서드는 http:// ip : port / index 까지의 url에 매핑됨

자바로 구현할 수 있는 웹 컴포넌트

Catalina로 jsp로 보내서 servlet으로 변환, stream으로 브라우저에 출력

http:// ip : port / context / action에서
context까지 매핑: @requestmapping
action까지 매핑: @get @post @put @patch @delete

dto를 리액트에서 읽을 수 있도록 json으로 변환하는 거: Jackson

dependency injection 어노테이션
@RequiredArgConstructor로 final로 선언

@inject

@Qualified

yml 파일에 xml 경로를 줘야함(외부 경로이기 때문에)

mapper에 매개변수와 리턴 타입만 주면 됨

parameter 받는 어노테이션
@requestparam: queryString으로 데이터가 들어옴
파라미터 갯수가 변할때마다 다시 작성하기 귀찮으니 매개변수로 DTO를 받을 수 있음
이때 dto, table의 컬럼, queryString의 변수 이름이 같으면 자동으로 바인딩됨
param 형태로 넘어올때 dto에 setter를 정의해놓지 않으면 자동으로 바인딩을 못함
dto로 넘어온 걸 mapper까지 전달

@autowired로 컨테이너로부터 자동으로 주입받을 수 있음
매번 다른걸 주입받을때마다 쓰긴 귀찮고, 인터페이스를 주입하면 안됨(상속 받는 클래스 중 누굴 주입받을지 애매하니까)
변수명으로 상속 받는 클래스의 이름(앞에 대문자는 소문자로)을 넣으면 그 클래스를 자동으로 가져옴

@Service 어노테이션에 value로 이름을 부여하고, @Resource 어노테이션으로 이름을 명시해서 인터페이스를 주입해도 클래스가 들어감 - layered architecture
