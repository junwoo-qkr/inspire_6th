통신의 종류
1. 동기
- http를 사용하는 rest api 호출
- 요청을 보낸 후 응답이 올 때까지 다른 일을 할 수 없음
- 강력한 데이터 일관성(클라이언트/서버가 사용중인 데이터가 동일)
2. 비동기
- 요청을 보낸 후 응답을 기다리지 않고 다른 작업을 함
- 최종적 일관성(처리 중간엔 일관성이 깨질지도 모르지만 처리 완료 후에는 데이터가 일관적이게 됨)
- amqp를 사용할 수 있음

rest template(legacy) 실습
- resttemplate 객체를 bean으로 등록해놔야함
- restemplate.exchange의 파라미터
  - url
  - 요청 타입
  - 보낼 객체
  - 응답을 받을 타입
- 사용자 조회 시 orderList에 빈 리스트를 넣던걸 수정 -> order-service에서 주문목록을 가져오도록 함

resttemplate에 @loadbalanced 추가하면 설정 파일에서 url을 service-discovery에 등록된 서비스 이름으로 변경할 수 있음

feignclient
- rest api를 호출하기 위한 방법 중 하나
- rest call을 추상화한 spring cloud Netflix 라이브러리
- 사용방법
  - 호출하려는 엔드포인트에 대한 interface 생성(@FeignClient 선언)
  - interface의 메서드를 사용해서 다른 서비스의 엔드포인트에 요청
- 로그 추적 방법
  - 설정 파일에 서비스의 로깅 레벨 변경
  - 서비스 실행 파일에 Logger.Level 클래스 선언

feignException
- 일부러 잘못된 엔드포인트로 요청을 보내고, FeignException을 catch해서 예외를 처리해보기

FeignErrorDecoder 구현
- feign 관련 예외를 한 곳에서 모아서 처리
