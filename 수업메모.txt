동일한 서비스를 여러개 켜놓으면:
- 데이터가 분산 저장 -> 데이터 동기화 문제
-> 인스턴스마다 고유의 DB를 갖는게 아니라 동일 서비스는 외부에 있는 하나의 DB를 사용하도록 설정
-> 또는 메시지 브로커를 통해 인스턴스마다 가지는 DB를 동기화
-> 또는 각 인스턴스가 메시지 브로커(미들웨어)를 통해 외부의 DB에 접근(Kafka Connector + DB)

kafka
- 링크드인에서 개발, 2011년에 오픈소스화
- scala 언어로 된 오픈소스 메시지 브로커
- producer가 발행한 메시지를 구독중인 consumer에 전송
- 한 메시지를 여러 consumer에게 허용
- 높은 처리량을 위한 메시지 최적화
- 브로커를 scale-out 가능
- eco-system

end-to-end 연결 방식의 아키텍처
- 데이터 연동의 복잡성 증가
- 서로 다른 데이터 pipeline
- 확장이 어려운 구조

kafka broker
- 실행중인 kafka 애플리케이션 서버
- 3대 이상의 broker cluster 구성 권장
  - 옛날엔 zookeeper가 controller 기능을 수행함
  - n대의 broker 중 1대는 controller 기능 수행
    - 파티션 할당
    - 모니터링

spring kafka 사용
- docker에서 최신 apache kafka pull
- 컨테이너 시작: docker run -p 9092:9092 --name broker apache/kafka:latest
- 실행중인 컨테이너 접속: docker exec -it broker bash
- topic(카테고리별 저장 공간) 생성: ./opt/kafka/bin/kafka-topics.sh --create --topic quickstart-events --bootstrap-server localhost:9092
- topic 목록: ./opt/kafka/bin/kafka-topics.sh --list --bootstrap-server localhost:9092
- 특정 topic 상세 정보: ./opt/kafka/bin/kafka-topics.sh --describe --topic quickstart-events --bootstrap-server localhost:9092
- topic에 이벤트 추가: ./opt/kafka/bin/kafka-console-producer.sh --topic quickstart-events --bootstrap-server localhost:9092
- 이벤트 읽기: ./opt/kafka/bin/kafka-console-consumer.sh --topic quickstart-events --from-beginning --bootstrap-server localhost:9092
  -> 이벤트를 추가할 때마다 실시간으로 읽음
  -> from-beginning 옵션이 없으면 topic에 연결되기 전의 이벤트는 읽지 않음
