hysterix dashboard + turbine server는 deprecated -> micrometer + prometheus를 사용
- micrometer로 각 마이크로서비스의 정보 수집, prometheus로 정보 저장, grafana로 시각화

micrometer
- jvm 기반으로 앱의 metrics 제공
- Prometheus 등의 다양한 모니터링 시스템 지원
- actuator가 필요

timer
- 짧은 지연 시간, 이벤트의 사용 빈도 측정
- 시계열로 이벤트의 시간, 호출 빈도 등을 제공

user-service, order-service, apigateway-service에 실습
- 의존성 추가, yml 파일에 엔드포인트과 observations.annotations.... 추가
- controller의 메서드에 @Timed 추가
  - @Timed의 value 값으로 정보가 저장됨(넣지 않아도 상관 없음, 사용자화하고 싶거나 service의 메서드에서 정보를 수집하고 싶거든 쓰기)
  - longTask=true: 실행중인 작업에 대해서 정보 수집(너무 짧은 작업에 적용하면 정보 수집이 안됨)
- /actuator/metrics: 조회 가능한 지표 목록(한번이라도 호출한 api만 뜸)
- /actuator/prometheus: 수집한 정보

Prometheus
- metrics를 수집하고 모니터링, 알람에 사용되는 오픈소스 애플리케이션
- pull 방식의 구조와 다양한 metric exporter 제공
- 시계열 DB에 metrics 저장 후 조회 가능

Grafana
- 데이터 시각화, 모니터링 및 분석을 위한 오픈소스 애플리케이션
- 시계열 데이터 시각화를 위한 대시보드 제공

실습
- Prometheus 설치
- prometheus.yml 수정(target 지정)
- Prometheus 실행(./Prometheus --config.file=prometheus.yml)
- 대시보드 접속: localhost:9090
- http_server_requests_seconds_count, http_server_request_seconds_max, http_server_requests_seconds_sum 등으로 정보 검색
  - uri: 요청했던 uri
  - uri=UNKNOWN인 것: gateway의 역할을 했던 요청이라 전달만 해줬기 때문
- graph 확인
- docker로 Grafana 설치
- grafana에 Prometheus 연동
- 대시보드 생성(JVM(micrometer), Prometheus, spring cloud gateway)
  - Prometheus 대시보드: ${DS_THEMIS}를 datasource.name으로 변경
  - spring cloud gateway 대시보드: gateway_requests_seconds_count 앞에 spring_cloud_ 붙이기, job의 이름을 apigateway-service로 변경, field를 numeric fields로 변경, ...
