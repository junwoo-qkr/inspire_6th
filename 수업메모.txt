원래 프로젝트 구조: monolithic
- 다양한 서비스가 한 프로젝트 안에 존재
- 접근 용이
- 한 서비스에 에러가 나면 전부 작동하지 않음
- 클라우드 환경에 부적합
    - scale out(똑같은 서버 증설) 등이 제한적

msa: micro service architecture
- 한 프로젝트에는 한 서비스만 존재
- 요청, 응답은 게이트웨이를 통과
- 각 서비스가 discovery service에 등록되어 있어야함
- 각 서비스 간의 통신은 비동기 방식으로
- 서비스들은 cluster(spring cloud)로 묶여있어야함
- scale out이 간편
- monolithic보다 복잡
- db의 트랜잭션을 유지하기 어려움

spring cloud framework
- spring boot 기반으로 제작

discovery service
- 서비스들을 관리하는 서버
- netflix의 Eureka Server 등

api gateway: 단일 진입점 = 대표 도메인
- 외부 서버와 내부 서버 분리 가능
