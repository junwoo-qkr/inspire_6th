entity로는 레이어 간 전송 하지 말기
-> dto로 요청 받기 -> entity로 바꿔서 db랑 연동 -> dto로 다시 바꿔서 응답

@Entity: 엔티티임을 알리는 어노테이션
@Id: 기본키임을 알리는 어노테이션
@Table: 테이블의 속성을 명시하는 어노테이션
@Column: 컬럼의 속성을 명시하는 어노테이션
@GeneratedValue: 외부 값으로 값을 채울거라고 명시하는 어노테이션
@<One, Many>To<One, Many>: 일대다, 다대다, 일대일 관계 설정
- mappedBy: 관계를 형성할 컬럼 이름
- orphanRemoval: remove cascade 설정
- fetch: 가져오기 전략
- optional: null값 허용 여부
@JoinColumn: 외래키로 뭘 가져올지 명시

hibernate가 외래키 관계를 관리하도록 해야함
fetch시 외래키 관계로 묶인 테이블도 다 가져와버림 -> FetchType.LAZY로 설정

@JoinColumn(name = "email")
private UserEntity writer;
-> entity에서 변수의 이름은 writer지만 생성된 컬럼 이름은 email(외래키이기 때문)

외래키에는 값이 아니라 객체가 담김

mapper는 프레임워크가 관리하는게 아니었지만 @Repository는 프레임워크가 관리
<dd, dd>: 테이블을 만드는 엔티티, 기본값
