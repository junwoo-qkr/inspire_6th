CSR(Client Side Rendering) vs SSR(Server Side Rendering)

전통적인 인증 시스템
- 로그인이 완료되면 세션아이디를 쿠키로해서 클라이언트에 전달
- 쿠키에 담긴 세션아이드로 로그인 유지
- 세션은 서버 메모리에 저장 -> 서버가 여러대이거나 서비스가 나뉜 환경에서는 공유 세션 저장소가 필요
- 쿠키는 브라우저 중심 방식 -> 네이티브 모바일 앱에서는 직접 관리해야 함
token 기반 인증 시스템
- 로그인이 완료되면 토큰을 클라이언트에 전달
- 토큰으로 로그인 유지

jwt의 장점
- 클라이언트 독립적인 서비스(서버에 관련 정보를 저장하는 것이 아님) -> stateless
- cdn
- no cookie-session
- 지속적인 토큰 저장

spring cloud config
- 분산 시스템에서 필요한 설정 정보를 외부 시스템에서 관리
- 설정 변경 시 각 서비스를 다시 빌드할 필요 없음
- dev, uat, prod 환경에 맞는 설정 정보를 사용할 수 있음
(uat: user acceptance test)

설정 정보에 대한 우선순위
application-name-<profile>.yml > application-name.yml > application.yml(원격) > application.yml(로컬)

프로필을 지정하면 지정한 설정 파일과 전역 파일을 같이 가져옴(순위는 프로필이 지정된 설정이 더 높음)

설정 수정 후 서버에 반영하기 위한 방법
- 서버 재기동
- actuator refresh
- spring cloud bus
