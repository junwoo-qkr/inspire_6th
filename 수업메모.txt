추상화
자바는 단일 상속을 지향
다중 상속 시 두 부모에 똑같은 요소가 정의되어 있으면 어떤걸 상속받을지 애매해짐
추상 클래스(abstract class)
- 추상 메서드를 포함하고 있음
- 객체 생성이 안됨
- 추상 클래스의 자식들은 추상 메서드를 오버라이딩해야 함 -> 오버라이딩 안하면 자식도 추상 클래스가 됨
- 추상 메서드를 통해 표준화 가능(자식들은 추상 메서드를 커스터마이즈 하게됨)
인터페이스(interface)
- 객체 생성이 안됨
- 추상 메서드와 static final(상수)로만 이루어져 있음
- 객체의 타입을 숨길 수 있음
- 클래스가 인터페이스를 구현: implements
- 인터페이스가 인터페이스를 상속: extends
- 인터페이스의 자식 클래스도 추상 메서드를 오버라이딩 해야 함
- 인터페이스를 이용해 표준화 가능
- 인터페이스에 선언하는 추상 메서드는 abstract 빼도 됨(상수도 static final빼도 됨)

추상 메서드는 구현부가 없음
추상 클래스도 타입의 다형성은 구현 가능(추상클래스 이름 = new 추상클래스를상속하는클래스)
추상 클래스(인터페이스)로 배열도 만들 수 있음 -> 자식 클래스로 만든 객체로 채우기
인터페이스는 다중으로 implement 가능
 
표준만 만들고 싶다 -> 인터페이스
