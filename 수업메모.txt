microservice간 통신 시 연쇄 오류
- 한 서비스를 호출할 때 다른 여러 서비스에 요청을 보내고, 그 서비스 중 하나만이라도 장애가 생기면 500에러 발생
-> circuitbreaker로 장애가 일어난 부분을 차단, 대체 기능을 호출(fallback)

circuitbreaker
- 장애가 발생하는 서비스를 반복호출하지 않도록 차단
- 특정 서비스 장애시 다른 기능으로 대체 수행 -> 장애 회피
- 사용할 라이브러리: resilience4j(Netflix hystrix는 deprecated)
  - (resilience4j의 패턴: circuitbreaker, ratelimiter, bulkhead(호출 제한), retry, timelimiter)
- 실습
  - circuitbreakerfactory(circuitbreaker 객체를 생성하는 factory) 생성

사용자 지정 circuitbreakerfactory 만들기
- Resilience4Jconfig -> 빌더 패턴으로 factory 생성
- 따로 의존성 주입할 건 없음(이미 앞에서 함)
- order-service가 한번씩 10초동안 멈춰있도록 설정하고 켜기 -> 아까와 똑같이 요청 보내기

resilience4j의 circuitbreaker도 yml 파일에서 구현 가능

zipkin
- twitter에서 사용하는 분산 환경의 추적 시스템(오픈소스)
- collector, query service, database webui로 구성
- span: 하나의 요청에 사용되는 작업의 단위
- trace: 트리 구조로 이루어진 span set
  - 하나의 요청에 대해서 생기는 span들에는 같은 trace ID 발급

spring cloud sleuth(deprecated) -> micrometer trace를 사용

실습 내용:
- docker에 zipkin 설치/실행: docker run -d --name zipkin -p 9411:9411 openzipkin/zipkin
