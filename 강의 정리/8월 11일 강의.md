### 8월 11일 강의 \- AI 서비스 개발을 위한 백엔드 아키텍처 핵심 정리

본 문서는 2026년 8월 11일 진행된  **'AI 서비스 개발을 위한 백엔드'**  강의의 전체 내용을 백엔드 아키텍트의 관점에서 재구성한 기술 지침서입니다. 자바의 기초 문법을 넘어, 현대적인 클라우드 네이티브 환경과 기업형 시스템 아키텍처를 설계하기 위한 전략적 배경을 담고 있습니다.

#### 1\. 강의 개요 및 전략적 배경

현대 개발 생태계는 \*\*비즈니스 애플리케이션 개발(Java 트랙)\*\*과 \*\*데이터 분석/AI(Python 트랙)\*\*라는 명확한 투트랙으로 운영됩니다. 본 강의는 기업의 핵심 로직을 담당하는 자바 트랙을 중심으로 백엔드 개발자의 확장된 스펙트럼(Full-stack, DevOps, Cloud-native)을 다룹니다.

##### 1.1 기술 스택 선정의 전략적 근거 (JDK 17\)

단순히 최신 버전을 쫓는 것이 아니라, 프로젝트의 안정성과 생태계 호환성을 고려한 아키텍처적 의사결정이 필요합니다.

* **왜 JDK 17인가:**  최신 LTS(Long-Term Support) 버전 중 하나로, Spring 4.0 이상에서의 버전 이슈와 OpenAI 관련 라이브러리 지원 현황을 고려할 때 가장 검증된 절충안입니다.  
* **레거시와 현대의 가교:**  현업의 8, 11버전 시스템과 향후 21버전 이상의 서버리스 환경을 모두 포용할 수 있는 아키텍처적 유연성을 확보하기 위함입니다.

##### 1.2 한국 시장과 자바의 지배력

한국의 공공기관, 금융, 대기업 ERP 시스템은 2000년대 초반 웹 부흥기 이후 자바를 기반으로 구축되었습니다. 이 방대한 시스템의 안정적 유지보수와 고도화를 위해 자바는 대체 불가능한 핵심 역량으로 자리 잡고 있습니다.

#### 3\. Part 2 자바 핵심 개념 및 아키텍처 심층 분석

##### 3.1 자바 실행 환경과 플랫폼 독립성

자바의 핵심 철학은 \*\*'Write Once, Run Anywhere'\*\*입니다.

* **JVM (Java Virtual Machine):**  OS 위에 가상 머신을 씌워 애플리케이션이 플랫폼에 종속되지 않게 합니다.  
* **바이트 코드(.class):**  소스 코드는 JVM이 이해하는 바이트 코드로 컴파일되며, 이는 하드웨어가 직접 실행하는 바이너리 코드와 구분되는 중간 단계의 언어입니다.**실습 가이드:**  JAVA\_HOME은 JDK 설치 경로를 가리키며, Path에 %JAVA\_HOME%\\bin을 등록하는 이유는 콘솔 어느 위치에서든 컴파일러(javac)와 실행기(java)를 호출하기 위함입니다.

##### 3.2 객체지향 프로그래밍(OOP)의 근간: 클래스와 인스턴스

"클래스는 붕어빵 틀(설계도)이고, 인스턴스는 그 틀을 통해 구워져 나온 실제 붕어빵(메모리 객체)이다."

* **아키텍처적 설계 원칙:**  좋은 아키텍처는 \*\*높은 응집도(Cohesion)\*\*와 \*\*낮은 결합도(Coupling)\*\*를 지향합니다. 클래스를 쪼개는 이유는 각 클래스가 단 하나의 책임만 지게 하여 유지보수성을 극대화하기 위함입니다.  
* **메모리 소유권:**  변수와 메서드는 클래스 내부에 정의되지만, 실제 사용을 위해서는 new 연산자를 통해 인스턴스를 생성해야 합니다. 소유권은 클래스가 아닌 인스턴스에 있습니다.

public class Teacher {  
    private String name; // 인스턴스 소유의 변수  
    public void teach() { // 인스턴스 소유의 메서드  
        System.out.println(name \+ " 선생님의 강의");  
    }  
}

##### 3.3 변수 타입 체계 및 데이터 처리

자바는 8종의 기본 타입(Primitive)과 주소값을 참조하는 참조 타입(Reference)으로 나뉩니다.| 타입 분류 | 타입명 | 용도 | 크기 | 기본값 || \------ | \------ | \------ | \------ | \------ || **정수형** | byte, short, int, long | 숫자 데이터 | 1\~8 byte | 0 || **실수형** | float, double | 소수점 데이터 | 4, 8 byte | 0.0 || **문자형** | char | 단일 문자 | 2 byte | '\\u0000' || **논리형** | boolean | 참/거짓 | 1 byte | false |

* **심화 분석:**  char는 내부적으로 유니코드(숫자)로 관리되므로 int로의 묵시적 형변환이 가능합니다. String은 참조 타입임에도 리터럴 할당이 가능하도록 특수 설계되어 java.lang 패키지에 기본 탑재되어 있습니다.

##### 3.4 생성자와 메서드 전략

\*\*생성자(Constructor)\*\*는 인스턴스 탄생의 순간을 정의합니다.

* **마음이 착한 사람에게만 보이는 생성자:**  클래스에 생성자를 명시하지 않으면 자바 컴파일러가 매개변수 없는 '기본 생성자'를 묵시적으로 넣어줍니다.  
* **생성자 오버로딩:**"배스킨라빈스 31처럼, 사용자가 원하는 옵션(매개변수)에 따라 다양한 방식으로 객체를 생성할 수 있는 유연성을 제공합니다."  
* **this 키워드:**  지역 변수와 멤버 변수의 이름이 같을 때, 인스턴스 자신을 가리켜 혼선을 방지합니다.

##### 3.5 데이터 캡슐화와 정보 은닉

* **private:**  외부의 무분별한 접근을 막아 데이터 오염을 방지합니다.  
* **public (Getter/Setter):**  데이터를 검증된 방식으로만 수정/조회하도록 통로를 제한합니다. 이는 시스템의 안정성을 보장하는 보안적 장치입니다.

#### 4\. 현대적 자바 개발 기법: DTO와 롬복(Lombok)

##### 4.1 데이터 그릇의 구분: DTO, VO, Entity

현대 아키텍처에서는 데이터를 목적에 따라 명확히 구분합니다.

* **DTO (Data Transfer Object):**  프런트엔드와 통신(JSON)하기 위해 데이터를 담는 전송 전용 객체.  
* **VO (Value Object):**  값 자체가 논리적 의미를 가지는 객체 (주로 불변).  
* **Entity:**  DB 테이블과 직접 매핑되어 비즈니스 로직의 핵심 생명주기를 관리하는 객체.  
* **공통점:**  모두 데이터를 담는 그릇이며, 이들 사이의 관계를 \*\*'Has-a 관계'\*\*라고 합니다.

##### 4.2 빌드 도구와 YAML의 선호 이유

* **Maven vs Gradle:**  현대 아키텍처에서는 유연성이 높은 Gradle을 주로 사용합니다.  
* **왜 YAML인가:**  클라우드 네이티브 환경(Kubernetes, Docker)과 CI/CD 파이프라인에서 IaC(코드형 인프라) 환경과의 호환성이 뛰어나기 때문입니다. 가독성 또한 기존 XML보다 압도적입니다.

##### 4.3 롬복(Lombok)과 빌더(Builder) 패턴

@Builder 어노테이션은 많은 매개변수를 가진 생성자의 순서를 외울 필요 없이, 메서드 체이닝을 통해 가독성 있게 객체를 생성하게 해줍니다.

#### 5\. 형변환(Casting)과 래퍼 클래스(Wrapper Class)

* **Casting:**  큰 타입에서 작은 타입으로 변환할 때는 (int)와 같이 명시적 형변환이 필요하며 데이터 손실을 감수해야 합니다.  
* **Wrapper Class (Integer, Double 등):**  
* **박싱/언박싱:**  기본 타입을 객체로 감싸는 과정입니다.  
* **실무적 이유:**  ORM 프레임워크 연동 시, 데이터가 존재하지 않는 경우(null)를 표현하기 위해서는 기본 타입(int)이 아닌 래퍼 객체(Integer)가 필수적입니다. 이는 객체 지향적 데이터 핸들링의 핵심입니다.

#### 6\. 결론 및 학습 마무리

오늘 강의의 핵심 요약:  **"자바의 모든 아키텍처적 설계는 인스턴스 생성을 위한 클래스의 완벽한 정의로부터 시작된다."**  백엔드 개발자로서 객체지향적 사고를 갖춘다는 것은 복잡한 비즈니스 도메인을 독립된 클래스로 응집력 있게 설계하고, 이들을 유연한 관계(Has-a)로 연결하여 견고한 시스템을 구축하는 능력을 의미합니다.

##### 중요 용어집

* **JDK/JVM:**  자바 개발 도구와 실행 환경을 제공하는 가상 머신.  
* **바이트 코드:**  JVM 위에서 동작하는 운영체제 독립적 실행 코드.  
* **캡슐화:**  private과 Getter/Setter를 통한 정보 보호 기법.  
* **Has-a 관계:**  한 객체가 다른 객체를 멤버 변수로 소유하는 관계.  
* **YAML:**  클라우드 인프라와 호환성이 높은 가독성 좋은 설정 형식.
